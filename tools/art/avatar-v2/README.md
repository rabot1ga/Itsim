# avatar-v2 — слоистый аватар из мастеров

Пайплайн, который вырезает из PNG-мастеров webp-слои аватара (канвас
500×760) для `packages/content/layers/avatar_manifest.json` и
`packages/client/public/layers/avatar-v2/`. Клиент ничего не подгоняет:
`buildLayerStack()` (`packages/client/src/components/room/layers.ts`) просто
складывает `/layers/<file>` по `zOrder`, поэтому посадка решается здесь, на
этапе сборки.

## Файлы

|                                  |                                                                                                                   |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `../avatar-key.mjs`              | движок: хромакей, геометрия тела, посадочные профилы слотов (`slotTargets`), `strip`, `tintable`, `faceClearance` |
| `build.config.json`              | список «мастер → слой» (38 записей). Единственное место, где надо править состав сборки                           |
| `build.mjs`                      | прогон списка, `--only=<подстрока>`, `--publish`, `--config=`, `--allow-missing`                                  |
| `check-placement.mjs`            | QA-страж: измеряет опубликованные слои и сверяет с лендмарками; проверяет и ссылки манифеста                      |
| `preview.mjs`, `preview-all.mjs` | QA-рендеры в `artifacts/` (глазами)                                                                               |
| `masters/`                       | PNG-исходники. **В git не попадают** (42 МБ на набор)                                                             |
| `layers/`                        | выход сборки. **Тоже не в git** — в репозиторий едет только копия в `public/`                                     |

## Как устроена посадка

Никаких ручных коэффициентов на слой — их нечем измерить, и они расползаются
при первой же смене мастера. `bodyGeometry()` мерит манекен (лицо, разлёт рук,
размах ног), `slotTargets()` превращает мерку в **бокс слота**, `placeFit()`
заполняет бокс одним из режимов:

- `fit: 'width'` — масштаб по ширине, аспект сохраняется. Для объёмных вещей:
  волосы, головные уборы, топы.
- `fit: 'height'` — то же по высоте.
- `fit: 'box'` — бокс заполняется целиком, anisotropically. Единственный режим,
  который способен **сплющить** предмет, поэтому он под замком: перекос
  `max(sx/sy, sy/sx)` сверх `MAX_STRETCH` (1.5) — ошибка сборки с числами в
  тексте. Нужен там, где у мастера свой аспект, а закрывать полосу тела надо
  полностью: низы (брюки/шорты).
- `fit: 'contain'` (по умолчанию) — вписать без деформации.

`strip: 'color'` выкигивает фон-магенту, `tintable` отдаёт слой шкалой серого
(см. «Тинтинг»), `faceClearance` вырезает полосу глаз. Сборка печатает
`перекос N×` у каждого слоя — это и есть метрика, по которой видно, что мастер
придётся перерисовывать, а не растягивать.

## Команды

```bash
npm run avatar:build -w tools/art              # собрать всё в layers/
npm run avatar:build -w tools/art -- --only=hair
npm run avatar:check -w tools/art              # измерить посадку (0 = годно)
npm run avatar:preview -w tools/art            # artifacts/preview.png, preview-all.png
npm run avatar:publish -w tools/art            # + скопировать в public/layers/avatar-v2
```

`avatar:check` по умолчанию мерит **опубликованный** набор
(`packages/client/public/layers/avatar-v2`) — то, что видит игрок, и то, что
проверяется в CI без мастеров. На ещё не опубликованный вывод сборки:
`npm run avatar:check -w tools/art -- --layers=layers`. Пули переопределяются
без правки конфигов: `AVATAR_MASTERS_DIR`, `AVATAR_LAYERS_DIR`.

## Порядок работы над слоем

1. Мастер кладётся в `masters/<batch>/<file>.png`, в `build.config.json`
   добавляется запись `{ "out": "<slot_id>.webp", "master": "<batch>/<file>.png", "slot": "<профиль>" }`.
2. `npm run avatar:build -w tools/art -- --only=<file>` — посмотреть `перекос`.
3. `npm run avatar:check -w tools/art` — цифры, а не ощущения.
4. `npm run avatar:preview -w tools/art` — проверить глазами поверх тела
   (лицо должно остаться лицом: глаза не под причёской).
5. Только когда check зелёный — `--publish` и правка манифеста.

## Тинтинг

В манифесте у `body` стоит `tintSlot: skinTone`, у `hair` и `beard` —
`hairColor`; `traitTint()` (shared/engine) собирает из палитры CSS-фильтр
`sepia(1) saturate(...) hue-rotate(...) brightness(...)`. Он работает только по
шкале серого, поэтому все эти мастера собираются с `tintable: true`
(`.greyscale()` в движке). Это и есть ответ на вопрос PR #10 «убивать ли
выбор цвета волос»: не убивать — слой обязан быть серым, тогда фильтр красит.

## Состояние (23.09.2026): набор принят, `avatar:check` зелёный

Перекалибровка 4b сделана: `✓ 38 собрано, 0 с проблемами`,
`✓ проверено 38 слоёв, 0 с нарушениями`, манифест переведён на v2 webp,
осиротевший SVG-слой `public/layers/avatar/` (41 файл) удалён.

Что было вылечено в движке, а не рисованием:

- низы (`bottom_*`) переехали на `fit: 'box'`: бокс = размах ног × полоса от
  пояса до щиколотки, перекос под замком `MAX_STRETCH`;
- волосы вернулись на `fit: 'width'` (плоский бокс давал перекос 1.52–1.93× и
  4 падения сборки), а «причёска вместо лица» лечится `faceClearance`;
- страж получил инвариант «лицо не закрыто» (непрозрачные пиксели в окне глаз
  ≤ 20 %) — bbox-меры этот дефект ловить не могут, именно он и был в PR #10;
- ссылки манифеста сверяются с файлами на диске: `validate:content` пути слоёв
  не знает, а битый путь в клиенте — просто пустое место в кадре.

## Долги, оставленные осознанно

- **`hair_long` / `hair_ponytail` нарисованы короткими** (до челюсти, не до
  плеч). Без перерисовки мастера не исправить: растягивать нельзя.
- **`bottom_sweatpants` (перекос 1.6×) и `bottom_suit` (1.63×)** сидят на
  `maxStretch: 1.7` точечно, в конфиге помечено `_debt`. Аспект исходника
  ~1.15 против 0.83 у слота. Перегенерацией не вылавливается: шесть прогонов
  дали разброс 0.46…1.88 хаотично — геометрию должен давать мастер, а не лотерея.
- **`bottom_chinos`** переведён на `b9/bottom_chinos.png` (аспект 0.59,
  перекос 1.43) — из трёх кандидатов b9 этот был ближе всех.
- **Окно `faceClearance` — прямоугольник** по bbox глаз. На канвасе 500×760
  при отображаемых ~120 px это не видно, но при крупном зуме (QA-рендеры ×3)
  кромка причёски читается срезом. Правильное решение — маска по форме лица в
  мастере, тогда `faceClearance` из движка уходит вовсе.
- **Рукава топов короче позы манекена.** `top` мёрится по разлёту рук в полосе
  плечо→грудь и проходит страж, но у худи (`top_hoodie_*`) рукав сужается ниже,
  и голые руки манекена торчат из-под него. Это мастер-артефакт: рукава нельзя
  ни дотянуть (перекос), ни дорисовать на этой стороне пайплайна — нужен
  перерисованный мастер под позу `mannequin-v1`.
- **Мастера кепок/шапок нарисованы на голове.** `acc_cap`/`acc_beanie` содержат
  саму голову, поэтому для них включён `faceClearance: 'face'` (вырезание лица от
  брови до подбородка). Цена — подрезанный по прямой козырёк; правильно —
  вычистить голову из мастера.
- **Цвет бороды наследует `hairColor`** (в `traitTint` нет `beardColor`) — как
  в main. Отдельный trait — задача на генетику + UI, не на арт.

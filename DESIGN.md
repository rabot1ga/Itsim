Этот документ описывает стратегию создания визуала, который обеспечивает уникальность каждого игрока при минимальных затратах на арты, а также техническую интеграцию с блокчейном Solana с учетом опыта создания NFT-коллекций на 10 000+.

## 1. Стратегия: Комбинаторика + Тинтинг + On-Chain Traits

Главная ошибка инди-игр — рисовать «готовые картинки комнат». Это тупик.
Стратегия повторяет пайплайн генеративных NFT-коллекций (HashLips / Art Engine), но с адаптацией под живой геймплей.

### Три кита процедурки:
1. **Слоистость (Layering):** Комната и персонаж собираются из 5-10 независимых PNG/SVG слоев с прозрачностью.
2. **Тинтинг (Hue-Shift):** Художник рисует ассет в оттенках серого. Движок красит его через CSS `filter` или Canvas `globalCompositeOperation`. *1 ассет × 12 цветов = 12 уникальных предметов.*
3. **On-Chain Seed (Solana):** Базовая «генетика» (цвет стен, форма окна, цвет глаз аватара) жестко привязывается к публичному ключу кошелька игрока.

## 2. Ассет-лист (Скоуп для художника на 7-9 дней)

*Все ассеты готовятся в едином разрешении (например, 1000x1000 для комнат, 500x500 для аватаров) с идеальным выравниванием по опорным точкам.*

### 👤 Аватар (Слоеный пирог)
| Слот | Кол-во баз | Вариативность (с тинтингом) | Редкость (для NFT-слоя) |
| :--- | :---: | :--- | :--- |
| **Тело (Skin)** | 3 | 6 оттенков кожи | - |
| **Глаза** | 10 | Уставшие, в VR, красные от кода | Common (70%), Rare (20%), Legendary (10% — «Глаза Сеньора») |
| **Прическа** | 15 | 12 цветовых палитр | - |
| **Борода/Усы** | 8 | Седина, щетина | - |
| **Верх (Одежда)** | 20 | Мерч «Corporation of Everything», худи `localhost` | Сезонные дропы |
| **Аксессуары** | 12 | Наушники, пирсинг, медальон | On-chain ачивки |
| **ИТОГО** | **~68 баз** | **> 100 000 комбинаций** | |

### 🏠 Комната (Интерьер)
Комната имеет **фиксированные слоты** (Игрок не двигает мебель, он *улучшает слоты*).
1. **Background (Фон):** 5 уровней (Общага → Пентхаус). Открывается по уровню дохода.
2. **Слот «Стена» (Декор):** Постеры, неон, серверные стойки, полки с книгами. (30 ассетов)
3. **Слот «Стол»:** От хлипкой парты до L-shaped standing desk. (8 ассетов)
4. **Слот «Кресло»:** Табуретка → Herman Miller → Трон. (6 ассетов)
5. **Слот «Сетап» (Техника):** Мониторы, ПК, клавиатуры. Меняется пачкой. (15 ассетов)
6. **Слот «Атмосфера»:** Растения, ковры, свет. (20 ассетов)
**ИТОГО:** ~80 базовых ассетов.

### 🐾 Питомец (Компаньон)
*Питомец должен быть анимированным (хотя бы 2 кадра: idle / sleep).*
* **Виды (6):** Кот, Корги, Кактус, Робот-пылесос, Тамагочи, Паук.
* **Аксессуары (15):** Ошейник с RGB, мини-худи, шляпа.
* **ИТОГО:** ~25 базовых ассетов.

**Гранд-тотал для художника: ~170 ассетов.** При правильной организации слоев это 1 неделя работы.

## 3. Процедурная генерация: Техническая архитектура (Solana + TMA)

Так как вы делали коллекции на 10k, вы знакомы с `traits.json` и `metadata`. Мы адаптируем этот подход под live-игру.

### 3.1. Детерминированный Seed (Генетика)
В отличие от классических NFT, где traits рандомятся при минте, в live-игре traits должны быть **привязаны к игроку**, но **изменяемы**.

```typescript
// Псевдокод генерации базового «генотипа» игрока
import { sha256 } from '@noble/hashes/sha256';
import { bytesToHex } from '@noble/hashes/utils';

function generatePlayerSeed(walletAddress: string, gameId: string): string {
  // Seed жестко привязан к кошельку. Игрок не может «рероллить» базовую генетику.
  const raw = `${walletAddress}:${gameId}:base_genetics`;
  return bytesToHex(sha256(new TextEncoder().encode(raw)));
}

function getGeneticTraits(seed: string) {
  // Детерминированный рандом на основе сида (как в HashLips)
  return {
    eyeShape: weightedPick(eyeOptions, seed, 'eye'),
    roomWindowShape: weightedPick(windowOptions, seed, 'window'),
    skinTone: pickFromPalette(skinTones, seed, 'skin')
  };
}
```
**Зачем это нужно:** Это создает «родословную». Игроки с определенными «генетическими» чертами могут объединяться в кланы или получать скрытые бонусы.

### 3.2. On-Chain Integration (Solana Metadata)
Когда игрок покупает крутое кресло (Herman Miller) или питомца за SOL/SPL-токены, это минтится как **Compressed NFT (cNFT)** или **Programmable NFT (pNFT)** через Metaplex.

**Структура Metadata предмета:**
```json
{
  "name": "Herman Miller Aeron",
  "symbol": "CHAIR",
  "attributes": [
    { "trait_type": "Slot", "value": "Chair" },
    { "trait_type": "EnergyBonus", "value": 2 },
    { "trait_type": "Rarity", "value": "Legendary" },
    { "trait_type": "LayerId", "value": "chair_herman_miller_01" }
  ],
  "properties": {
    "files": [{ "uri": "chair_hm.png", "type": "image/png" }]
  }
}
```
**Как игра это рендерит:**
1. Клиент (TMA) читает NFT из кошелька игрока (через Helius RPC или Solana Web3.js).
2. Извлекает `LayerId`.
3. Подгружает соответствующий PNG из CDN игры и накладывает в слот «Chair».
4. Сервер валидирует, что NFT действительно принадлежит этому `walletAddress` и применяет `EnergyBonus` к формуле из ТЗ (Раздел 4.3).

### 3.3. Cross-Collection Synergy (Киллер-фича)
Игра может читать **чужие** Solana NFT из кошелька игрока и давать бонусы:
* Держишь **SMB Gen2**? → Получаешь уникальный скин «Пиратская повязка» и +5% к фриланс-доходу.
* Держишь **Mad Lads**? → В комнате появляется постер с Mad Lad.
* Держишь **DeGods**? → Питомец-бульдог в костюме.

*Это обеспечит взрывной виральный рост в Solana-твиттере и комьюнити.*

## 4. Пайплайн для художника (NFT-style Workflow)

Чтобы художник не сошел с ума, а вы могли легко добавлять новые предметы, настройте пайплайн как для NFT-генерации:

1. **Figma / Photoshop с артбордами:**
   * Один артборд = один слот (например, `chair_base.psd`).
   * Все варианты кресел лежат в скрытых слоях внутри этого PSD.
2. **Экспорт через скрипт:**
   * Скрипт на Node.js/Python пробегает по папкам `assets/{slot}/*.png`.
   * Генерирует `manifest.json` (как в HashLips), где описаны веса (weights) и совместимость (compatibility).
3. **Валидация наложения:**
   * Скрипт генерирует 1000 случайных комнат *до того, как они попадут в игру*.
   * Вы визуально проверяете, что спинка кресла не перекрывает монитор, а питомец не летает в воздухе. (Это частая боль процедурки).

## 5. Виральность: Генерация «Скриншотов» (Sharing)

В ТЗ (Раздел 1.4) заявлен K-фактор ≥ 0.25. В Telegram Mini Apps главный драйвер шеринга — это **красивая картинка-результат**.

Используйте тот же скрипт, что генерил ваши 10k NFT, но на клиенте (или на edge-функции):
1. Игрок достигает вехи «Сеньор в 25 лет».
2. Скрипт рендерит его уникальную комнату + аватара в единую PNG-картинку (через HTML5 Canvas `toDataURL`).
3. Накладывает рамку с его статистикой и QR-кодом бота.
4. Игрок шерит это в Telegram/Twitter.

**Код генерации превью (упрощенно):**
```javascript
// Рендерим слои в Canvas в правильном z-order
const canvas = document.getElementById('share-preview');
const ctx = canvas.getContext('2d');

ctx.drawImage(backgroundImg, 0, 0); // Стена
ctx.drawImage(deskImg, 0, 0);       // Стол
ctx.drawImage(chairImg, 0, 0);      // Кресло
ctx.drawImage(petImg, 0, 0);        // Питомец
ctx.drawImage(avatarImg, 0, 0);     // Аватар
ctx.fillText("I reached Senior Dev in 78 days!", 50, 900);

// Сохраняем или шерим через Telegram WebApp API
window.Telegram.WebApp.switchInlineQuery('Смотри, моя IT-берлога!', ['users', 'groups']);
```

Художник заменяет файлы в `public/layers/` по конвенции из манифестов — код менять не нужно.

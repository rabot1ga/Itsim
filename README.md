# 💻 IT Life Simulator v2.0

**Telegram Mini App** — юмористический симулятор жизни IT-специалиста.

> «Блин, это буквально мой прошлый вторник.»

Игрок начинает после института (10 000 ₽, без работы) и строит карьеру: учит навыки,
работает, ходит на собеседования, получает повышения, обрастает вещами и питомцами,
следит за деньгами, здоровьем, настроением, энергией и репутацией. Путь — от безработного
до CTO через выборы борта, с альтернативными финалами (выгорание, уход из IT).

## 🚀 Быстрый старт

### Требования

- Node.js 18+ (рекомендуется 20 LTS)
- npm 9+
- Python 3 (только для генераторов SVG-слоёв в `tools/`)

### Запуск

```bash
npm install
npm run dev
```

Поднимутся три процесса:

| Сервис          | Адрес                   | Что это                             |
| --------------- | ----------------------- | ----------------------------------- |
| Game API        | `http://localhost:3001` | Fastify-сервер, сервер-авторитет    |
| Mini App клиент | `http://localhost:5173` | React + Vite (прокси `/api` → 3001) |
| Telegram-бот    | `http://localhost:3002` | мок-режим без `BOT_TOKEN`           |

Отдельно:

```bash
npm run dev -w packages/server   # только API
npm run dev -w packages/client   # только клиент
npm run dev -w packages/bot      # только бот
```

### Переменные окружения

Полный список с комментариями — в [`.env.example`](.env.example) (`cp .env.example .env`).
Ключевые:

| Переменная                | Назначение                                              | Без неё                                                        |
| ------------------------- | ------------------------------------------------------- | -------------------------------------------------------------- |
| `BOT_TOKEN`               | валидация Telegram initData, Bot API (бот, счета Stars) | dev-режим: initData не проверяется, бот работает в mock-режиме |
| `JWT_SECRET`              | подпись токенов `/api/auth/telegram`                    | дефолт `'dev-secret'` (только для локалки!)                    |
| `TELEGRAM_WEBHOOK_SECRET` | аутентификация вебхука платежей                         | `/api/payments/webhook` отвечает 503                           |
| `ADMIN_TOKEN`             | общий секрет сервера и бота (`/api/admin/*`)            | у бота не работают `/stats` и `/delete_my_data`                |
| `MINI_APP_URL`            | URL мини-приложения для кнопки «Играть»                 | `https://itsim.app`                                            |

> 🔒 В `NODE_ENV=production` сервер **не стартует** с dev-дефолтами: пустой `BOT_TOKEN`,
> `JWT_SECRET=dev-secret`, пустой `TELEGRAM_WEBHOOK_SECRET` или включённые mock-платежи —
> это ошибка запуска, а не предупреждение (`packages/server/src/config.ts`).
> Деплой описан в [docs/deploy.md](docs/deploy.md).

```
│   ├── server/     # Fastify API, сервер-авторитет, персистентность, платежи
│   ├── client/     # React 18 + Vite 5 + Tailwind + Zustand 4
│   ├── bot/        # Telegram-бот: long polling / webhook, команды, уведомления
│   └── sim/        # симулятор баланса + статистика событий
├── tools/
│   └── art/                      # инструменты рукотворного арта (webp-публикация, проверки)
├── docs/
│   ├── design.md    # дизайн-документ клиента (§1–16 + роадмап §15, 10/10 закрыт)
│   ├── deploy.md    # деплой, переменные окружения, вебхуки, бэкапы, GDPR
│   └── pixel-art.md # ТЗ пиксельного пайплайна
├── ci/github-actions-ci.yml  # workflow: типы + eslint + контент + тесты + симулятор + сборка
├── .env.example              # все переменные окружения с комментариями
├── SPEC.md    # техническое задание v2.0
├── DESIGN.md  # процедурная генерация + Solana-интеграция

```

| Пакет     | Роль                                                     | Объём                                                                                                                  |
| --------- | -------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `shared`  | движок (чистые функции) + схемы + типы + миграции сейвов | ~1.5k строк, 198 юнит-тестов                                                                                           |
| `content` | контент в JSON + загрузчик/валидатор                     | 37 файлов, ~600 KB, CLI-гейт                                                                                           |
| `server`  | Fastify 4, сервер-авторитет                              | ~3.8k строк (`routes/game/` — 11 файлов: state/action/day/sprint/archetype/interview/ending/misc + shared), 108 тестов |
| `client`  | React 18 + Vite 5 + Tailwind + Zustand                   | 5 вкладок + MORE-меню (14 экранов)                                                                                     |
| `bot`     | Telegram-бот (Bot API, polling/webhook/mock)             | 4 файла, 22 теста                                                                                                      |
| `sim`     | симулятор баланса + тулстатистика событий                | 2 скрипта                                                                                                              |

### Ключевые архитектурные решения

1. **Сервер-авторитет.** Вся игровая логика — на сервере. Клиент отправляет
   намерение (intent), сервер вычисляет эффекты. Клиент использует те же функции
   из `@itsim/shared` для оптимистичного предпросмотра, но источник правды — сервер.
2. **Offline-начисление энергии.** 1 игровой день = 3.5 реальных часа, максимум 7 дней
   в банке. Расчёт только по серверному времени (`lastTickAt`, `bankedDays`).
3. **Контент как данные.** Весь гейм-контент в JSON. Правка баланса = правка JSON,
   без релиза клиента. Валидация через Zod живёт в самом пакете `@itsim/content`:
   один и тот же код гоняют сервер при старте и CI (`npm run validate:content`),
   cross-reference проверки возвращают структурированные issues (error/warning).
4. **Движок — чистые функции.** `packages/shared/src/engine/` не знает ни про HTTP,
   ни про React: одни и те же функции используют сервер, клиент и симулятор.
5. **Узкие интерфейсы под замену.** Хранилище (`load/save/delete`) — интерфейс;
   сейчас за ним JSON-файлы, в проде — PostgreSQL без переделки роутов.
6. **Сейвы версионируются.** У каждого сохранения есть `version`; при загрузке оно
   прогоняется через `migrateState()` (`shared/engine/migrations.ts`) и перезаписывается,
   если что-то изменилось. Миграции идемпотентны, а сейв, записанный более новой версией
   сервера, не трогается — откат билда не портит данные.
7. **Безопасные дефолты.** Все переменные окружения — в `packages/server/src/config.ts`;
   dev-дефолты (незаданный `BOT_TOKEN`, `JWT_SECRET=dev-secret`, mock-платежи) в
   `NODE_ENV=production` приводят к отказу запуска, а не к тихой дыре.

## 🎮 Игра: ресурсы, цикл, грейды, финалы

### Ресурсы

| Ресурс        | Диапазон | Роль                                                                                     |
| ------------- | -------- | ---------------------------------------------------------------------------------------- |
| 💰 Деньги     | 0+       | ограничитель early game; еда, аренда, курсы, переезды                                    |
| ❤️ Здоровье   | 0–100    | долгосрочный ресурс; падает от переработок, лечится отдыхом                              |
| 😊 Настроение | 0–100    | краткосрочный ограничитель; дрейфует вниз каждый день (в коде и API — поле `motivation`) |
| ⚡ Энергия    | 3–16     | ресурс хода; макс. зависит от жилья и перков                                             |
| ⭐ Репутация  | 0–100    | гейт карьеры; растёт от работы и нетворкинга                                             |

### Игровой цикл

День → действия за энергию (учёба / работа / отдых / соц.) → событие с выбором →
«Завершить день» (нативная MainButton в Telegram) → зарплата/расходы/офферы →
новый день. Офлайн игра «ждёт»: энергия копится в банке дней.

### Этапы и грейды

| Этап              | Дни    | Что происходит                    |
| ----------------- | ------ | --------------------------------- |
| Early «Выживание» | 1–30   | навыки с нуля, первый оффер       |
| Mid «Рост»        | 30–150 | junior → middle → senior          |
| Late «Влияние»    | 150+   | teamlead → architect → выборы CTO |

Лестница: `unemployed → intern → junior → middle → senior → teamlead → architect → cto`.

### Финалы (`balance.endings`)

- 🏢 **Корпоративный бог** — CTO через выборы борта (special-gate, не повышение)
  **+ 60 дней в кресле**: с 22.10.2026 выборы дают должность, а не финал
- 🚀 **Экзит** — стартап за 100 млн+
- 💻 **Свободный художник** — фриланс
- 🎓 **Учитель** — репутация наставника + лидерство + глубина ремесла
  (условие ребалансировано 22.10.2026: мёртвый счётчик джунов убран)
- 🔥 **Выгорание** — терминальное состояние (мотивация/здоровье в нуле)
- 💀 **Ушёл из IT** — терминальное состояние

## 🔧 Механики

### ⚡ Энергия и офлайн-прогресс

- Текущая энергия (`energy/maxEnergy`, база 10) тратится на действия, восстанавливается сном и новым днём.
- Максимум энергии растёт от жилья и перков.
- Офлайн: 1 banked-день за 3.5 часа отсутствия, кап — 7 дней; трата — «полная энергия + 10 🔥».
- Всё считается по серверному времени, в `/state` отдаётся `offlineDaysEarned`.

### 💼 Карьера: гейты, ревью, конкуренция

Гейты грейдов — данные (`balance.careerGates`), а не константы в коде. Каждый грейд требует:

- глубину **основного** навыка (`mainSkillDepth`) и сумму по **его ветке** (`branchTotal`),
- общую ширину (`totalLevels`), коммуникацию / английский / лидерство,
- репутацию, минимум дней в грейде (`minDaysInGrade`).

Повышение — двухступенчатое: требования открывают **ревью**, а решает **слот компании**:
шанс `1 / (1 + competition · e^(−0.7·surplus))`. Квалификация «впритык» — долгое ожидание,
перекач — быстрый проход. Клиент показывает это карточкой `CareerPressureCard`
(стоимость дня + чего не хватает + кнопка выборов CTO).

### 🗳️ Выборы CTO и срок в кресле

CTO — не повышение, а `special`-гейт: экшен `cto_elect` с кулдауном `electionIntervalDays`.
Шанс — от репутации и лидерства; провал — минус репутация/мотивация и кулдаун борда.
Проверено смоук-тестом (архитектор rep 80/lead 34 → шанс 62%).

**Победа больше не заканчивает партию** (В2, 22.10.2026 —
[docs/PROPOSALS-2026-09-27-endgame.md](docs/PROPOSALS-2026-09-27-endgame.md)): выборы пишут
`ctoSinceDay`, а финал `corporate_god` открывается, когда кресло удержано
`balance.endings.cto.minDaysAsCto` дней (60) при прежних порогах репутации и лидерства.
Потеря работы снимает срок и возвращает грейд в `architect` — иначе уволенный CTO
досиживал бы финал безработным, а переизбраться не мог бы (`runCtoElection` пускает
только архитекторов). Правило одно на сервер и клиент: `ctoTenureDays()` +
`checkEndings()` в `@itsim/shared`, экран «Финалы» рисует срок тем же движком.
Сейв — версия 4, миграция `v4_cto_tenure` разбирает старые сейвы так: сидящему CTO
финал снимается (его ставили выборы, не игрок), потерявшему кресло — остаётся
(иначе `canStartNewLife` запер бы обе двери).

После CTO есть чем играть: 4 события с порогом `minGrade: cto` — первый квартальный
отчёт борду, ночной инцидент на проде, голосование о доверии и постмортем с бордом
(два последних цепочечные).

### 🎤 Собеседования-квиз

- 56 вопросов по 14 веткам навыков и 3 уровням грейда.
- Раздача «topic-first»: сначала вопросы основного навыка игрока, потом остальные подходящего уровня.
- Ответы с сервера не утекают; каждый ответ — обучение: верный +3 XP, неверный +2 XP + объяснение.
- `answerScore` 0.4–1.0 честно подмешивается в `interviewChance` (шанс оффера).
- Пропустил день собеседования — авторассмотрение; начал — квиз из 3 вопросов с резюме.

- **218 уникальных событий в 20 файлах**: daily, быт, погода, работа, учёба, деньги,
  семья, здоровье, соц., tech, mining, side-job будни, NPC-сюжеты, startup- и кот-цепочки,
  по 2 события на каждую ветку навыков, 44 follow-up'а на действия игрока.
- **Поздний этап** (с 27.09.2026): 8 событий с порогом `minGrade: architect` —
  защита своего выбора на борде, раскол легаси-монолита (за «выкатить молча» через
  две недели приходит цепочка), хантер с «тремя нулями» в оффере, keynote на две
  тысячи мест, проверка регулятора по персональным данным, список на 11 имён,
  преемник. До этого ни одно событие не имело порога выше `senior`: архитектор и
  CTO читали тот же котёл, что стажёр.
- **Слой CTO** (с 22.10.2026): 4 события с `minGrade: cto` — отчёт борду, ночной
  инцидент, голосование о доверии, постмортем. Порог живой, потому что CTO стал
  должностью: достижимость проверяет `packages/server/src/__tests__/endgameContent.test.ts`
  (прогон `pickEvent` по 600 дням в кресле + проверка, что архитектору они не выпадают).
- Условия: `cooldown`, `minGameDay`, `minMoney`, `maxOccurrences`, теги + `recentEventTags`
  (защита от повторов), отношения с NPC.
- Цепочки: `chainOnly`-события не попадают в случайный пул, приходят с задержкой `delayDays`.
- Статистика покрытия: `npx tsx packages/sim/src/events_stats.ts` — сколько событий видит
  игрок за 365 дней и размер пространства исходов.

### 🌳 Навыки, перки, мягкие навыки

- **34 навыка в 9 ветках**: frontend, backend, mobile, qa, devops, ai_ml, cybersec,
  gamedev, blockchain (Solidity, Web3, Rust для Solana, DeFi…). Гейтинг родитель → ребёнок,
  XP-кривая, шеринг XP по ветке (`branchShareXp`).
- **Выбор основного навыка**: тап по навыку в дереве — учёба/работа качают именно его
  (заблокированные ветки гейтятся на сервере).
- **8 перков** с реальными эффектами: энергия, скорость обучения, +% к фрилансу/майнингу/подработкам
  («Золотая лихорадка», «Подработчик»…). Открываются при выполнении требований.
- **Мягкие навыки** (коммуникация, английский, тайм-менеджмент, лидерство): нетворкинг —
  1 раз в день (`networking.dailyCap`), выше порога насыщения XP идёт с демпфером —
  митапы нельзя фармить бесконечно.
- **Английский**: бесплатные уроки и платный курс; открывает зарубежные компании.

### 💸 Стоимость жизни

- Бытовые расходы (`livingCosts`) списываются каждый день и растут с грейдом и жильём;
  при нуле денег — режим «гречка» (расходы урезаются, а не смерть).
- **Налог на капитал** (`wealthTax*`) раз в месяц: деньги «под матрасом» тают —
  день должен во что-то превращаться.
- **Переезды — привычка**: нужна подушка `saveMult ×` месячного платежа, удержанная
  `saveStreakDays` подряд (от 3×/25 дн до 15×/70 дн) + доходный барьер (`incomeGateMult`).
- Жильё 0–4 (Общага → Пентхаус): +maxEnergy, +мотивация/репутация; **переезд меняет фон комнаты**.

### 🖥️ Фриланс, 🛵 подработки, ⛏️ майнинг

- **Фриланс = отклик на бирже заказов**: заказ не выдаётся по кнопке. Игрок
  откликается (`freelance`, `params.projectId`, −3 ⚡, один отклик в день), и
  заказчик отвечает наутро: контракт с дедлайном и чек-листом задач, оплаченное
  тестовое задание (~6% суммы, минимум 500 ₽) или отказ. Шанс считает
  `bidChance`: 30% база, +40% за запас основного навыка над требованием, +20% за
  репутацию, −20% за размер гонорара, зажат в 10–90%. Cross-бонус SMB Gen2 +5%
  идёт на оплату тестового.
- **Верх биржи**: `platform_rescue` (900 000 ₽, порог 40) и `ml_governance`
  (1 800 000 ₽, порог 60). Планка держится «за задачу», а не «за чек»: при чеке
  от 400 000 `bidChance` уже отдаёт максимальный штраф за размер, поэтому
  сложность позднего подряда измеряется задачами и дедлайном, а не нулями.
- **Подработки (не IT)**: курьер, бариста, грузчик, таксист, ночной охранник,
  репетитор (платит от уровня навыка), стример — 1 в день, цена — энергия/здоровье/мотивация.
- **Майнинг-ферма**: пассивный крипто-доход. Оборудование (видеокарта → ферма → ASIC),
  счёт за электричество, солнечные панели (−50%), детерминированный волатильный курс.
  Ачивки «Подпольный майнер» (100k с фермы) и «Криптокит» (1M).

### 🐾 Питомцы 2.0

- 6 видов: кот, пёс, кактус, робот-пылесос, паук, бульдог. Кормление — 500 ₽/день
  (+мотивация, daily-кап `petFedToday`).
- Настроение от факта кормления (😿 голоден / 😋 сыт), CSS-анимация покачивания,
  статус-чип в комнате.
- Косметика из магазина: бант (3k), очки (5k), корона (15k) — рисуются поверх питомца,

### 🏆 Ачивки, челленджи, лидерборд, NPC

## 🖥️ Сервер и API

Fastify 4, сервер-авторитет. Контент валидируется Zod-схемами **при старте**
(15 групп файлов + cross-reference: эффекты `skill.X`/`relation.X`, id веток, id слоёв,
id навыков в вопросах, монотонность карьерной лестницы, каталог Stars). Состояние —
`packages/server/data/<telegramId>.json` (атомарная запись tmp+rename + in-memory кэш),
при загрузке прогоняется через миграции. Хранилище — бэкенд за узким интерфейсом:
JSON по умолчанию, `STORAGE=postgres` + `DATABASE_URL` — PostgreSQL через Prisma
(структуру держат SQL-миграции `src/db/migrations/*.sql`, перенос данных —
`npm run storage:import`).

### Auth

- `POST /api/auth/telegram` — обмен initData на JWT (HMAC-валидация при заданном `BOT_TOKEN`).
- Dev-режим: пустой токен → initData парсится без проверки подписи (id сохраняется,
  а не схлопывается в Dev/1, как раньше).
- Rate limit: 1000 req/мин на IP (`@fastify/rate-limit`), настраивается через env.
- Идемпотентность действий: `idempotencyKey` хранится **в самом сейве** (64 ключа, TTL 6 ч),
  поэтому повтор запроса безопасен и после рестарта сервера.

### Game (`/api/game`)

| Метод | Путь              | Назначение                                                             |
| ----- | ----------------- | ---------------------------------------------------------------------- |
| GET   | `/state`          | состояние игрока (+ `careerOutlook`, `costOfDay`, `offlineDaysEarned`) |
| POST  | `/action`         | универсальный экшен `{actionId, params, idempotencyKey}`               |
| POST  | `/advance-day`    | завершить день: зарплата, расходы, офферы, событие                     |
| POST  | `/event-choice`   | выбор в событии                                                        |
| POST  | `/unlock-perk`    | открыть перк                                                           |
| POST  | `/main-skill`     | выбрать основной навык                                                 |
| POST  | `/interview/start | answer                                                                 | finish` | квиз собеседования |
| POST  | `/reset`          | сбросить прогресс                                                      |

Экшены `/action` (30): `work_task`, `work_overtime`, `freelance`, `side_job`,
`study_book|course|mentor|stepik|advanced_course`, `study_english|english_course`,
`rest_sleep|walk|gym|bar|hobby`, `networking`, `pet_project`, `apply_job`,
`cancel_application`, `accept_offer`, `decline_offer`, `buy_item`, `upgrade_housing`,
`feed_pet`, `customize_room`, `customize_avatar`, `use_banked_day`, `cto_elect`,
`claim_ending`.

### Content (`/api/content`)

`manifest`, `companies`, `items`, `npcs`, `skills`, `career-gates`, `side-jobs`, `perks`, `achievements`.

### Leaderboard (`/api/leaderboard`)

`GET /friends|honest?limit=&offset=&metric=` — рейтинг из персистентных состояний через
**кэшируемый индекс** (полный скан не чаще раза в `LEADERBOARD_TTL_MS`, запись в индекс
на каждом сохранении). Ранжирование идёт по авторизованному пользователю: `isYou` больше
не врёт, а своя строка приходит отдельным полем `you`, даже если ты вне топ-20.
`honest` — доска без владельцев booster-предметов.

`metric` выбирает, по чему считать место: `rating` (итог, 0…1000) или одна из компонент
движка — `career` `skills` `money` `reputation` `achievements` `housing` (0…100).
Значение — ровно `ratingParts()` из `@itsim/shared` (engine/rating.ts): у доски нет и не
может быть своей формулы, поэтому вкладка «Деньги» обязана давать тот же порядок, что и
монотонная нормировка денег. Каждая строка несёт `score`, ответ — эхо `metric`;
неизвестная метрика — `400` со списком допустимых, а не тихий откат на `rating`.

### Payments (`/api/payments`) — Telegram Stars

| Метод | Путь            | Назначение                                                       |
| ----- | --------------- | ---------------------------------------------------------------- |
| GET   | `/products`     | каталог из `content/monetization.json` + что уже куплено         |
| POST  | `/stars`        | `createInvoiceLink` (XTR) на выбранный товар                     |
| POST  | `/webhook`      | обновления Telegram: `pre_checkout_query` и `successful_payment` |
| POST  | `/dev-complete` | локальная симуляция покупки (только `ALLOW_MOCK_PAYMENTS`)       |

Вебхук аутентифицируется секретом из `setWebhook` (`X-Telegram-Bot-Api-Secret-Token`,
сравнение constant-time), pre-checkout подтверждается (иначе Telegram отменяет платёж),
начисление идемпотентно по `telegram_payment_charge_id` (реестр `data/entitlements.json`).
Схема каталога запрещает продавать прогресс: только косметика, дни в банке и значки.

### Admin (`/api/admin`) — для бота

`POST /nudges` (кого позвать обратно + отметка «уведомлён»), `GET /users/:id/summary`
(данные для `/stats`), `DELETE /users/:id` (GDPR). Доступ по `x-admin-token`;
без `ADMIN_TOKEN` весь namespace отвечает 503, а не работает без защиты.

### Прочее

- `GET /health` — `{status, version, mode}` (`mode: 'dev'` = initData не проверяется).

## 🤖 Telegram-бот

`packages/bot` — настоящий бот на Bot API (`fetch`, без зависимостей). Режим выбирается сам:

| Режим     | Когда                                  | Что делает                                                                               |
| --------- | -------------------------------------- | ---------------------------------------------------------------------------------------- |
| `polling` | задан `BOT_TOKEN` (по умолчанию)       | long polling `getUpdates`, регистрирует команды через `setMyCommands`                    |
| `webhook` | `BOT_MODE=webhook` + `BOT_WEBHOOK_URL` | сам вызывает `setWebhook`, проверяет секретный заголовок                                 |
| `mock`    | нет `BOT_TOKEN`                        | `POST /webhook` отвечает тем, что **было бы** отправлено — вся логика тестируется офлайн |

Команды: `/start` (приветствие + кнопка `web_app`, deep link `startapp=ref_<id>`),
`/play`, `/help`, `/stats` (живая сводка через `/api/admin/users/:id/summary`),
`/delete_my_data` (реальное удаление сейва). Плюс фоновая рассылка «банк дней переполнен»:
бот раз в час забирает кандидатов из `POST /api/admin/nudges` — сервер сам помечает их
уведомлёнными, поэтому дважды одному и тому же человеку не прилетит.

Обработчики команд — чистые функции (`src/commands.ts`), покрыты 22 тестами.

## 📊 Баланс и симулятор

Баланс получен прогоном симулятора (40 агентов × 365 игровых дней, «разумный игрок»).

| Веха              | Медиана   | Цель      |
| ----------------- | --------- | --------- |
| Первый оффер      | 18        | 16        |
| Junior            | 33        | 30        |
| Middle            | 74        | 74        |
| Senior            | 142       | 150       |
| Teamlead          | 210       | 205       |
| Архитектор        | 299       | 285       |
| Жильё 1 / Жильё 2 | 162 / 256 | 203 / 286 |

Комплаенс поздней игры: architect до 250-го дня ≤ 25%, доля архитекторов ≥ 50%,
CTO за год ≤ 35% (эндгейм обязан оставаться трудным), выгорания ≤ 20%, тупиков 0.

Отдельный **эндгейм-зонд на двух годах** (40 × 730): на горизонте 365 дней до CTO не
доходит никто (0/40), то есть коридор «≤ 35% за год» мерил пустоту и не мог покраснеть
ни при каком балансе. Зонд меряет не сложность, а механику срока: 40/40 избраны
(медиана 390-й день), 40/40 забрали финал (медиана 450-й), срок между ними ровно 60 дней,
финалов не больше, чем избраний. Измерение за два года — 100% и 100%: потолок «≤ 35%»
в SPEC §4 про год, на двух годах это не гейт (разбор — [docs/ANALYSIS-2026-10-22.md](docs/ANALYSIS-2026-10-22.md) §4.5).

```bash
npm run simulate          # отчёт симулятора
npm test                  # контент + 447 юнит-тестов (движок/сервер/бот/клиент) + simulate --check
npx tsx packages/sim/src/simulate.ts --why   # что блокирует агента на следующем гейте
```

Что изменилось в v2.1 по сравнению с v2.0 (было: 100% игроков — архитекторы, деньги ничего не значили):

- **Грейды — данные, а не код** (`careerGates`): глубина основного навыка, ветка, ширина,
  мягкие навыки, репутация, период ревью, конкуренция.
- **Повышение ≠ автовыдача**: требования открывают ревью, решает слот с вероятностью от перебора.
- **Стоимость жизни работает**: ежедневные расходы, режим «гречка», налог на капитал, переезды-привычки.
- **Мягкие навыки не фармятся**: кап нетворкинга + демпфер насыщения.
- **Финалы достижимы**: выборы CTO + 60 дней в кресле, терминальные `burnout`/`left_it`.

[`ci/github-actions-ci.yml`](ci/github-actions-ci.yml), включён 23.10.2026;
см. [ci/README.md](ci/README.md)): на каждый push и PR гоняются
типы, eslint, prettier (`continue-on-error`), валидация контента, все три набора тестов,
симулятор и сборка. Отдельная джоба `content-guard` включается, только
если PR трогает `packages/content/**`: там валидация в `--strict` (предупреждения фатальны)
и обязательный прогон симулятора баланса.

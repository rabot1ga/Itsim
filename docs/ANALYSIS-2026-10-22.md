## 0. Резюме: почему последний PR не мержится

**PR #11 конфликтует с `main`, потому что 21.10.2026 в `main` влили PR #10.**
Обе ветки независимо добавили одни и те же пути, поэтому git даёт `add/add` на
бинарниках — автослияния для них не существует вовсе:

|                           |                                                                                                                                                       |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| head PR #11               | `1f69308` (`arena/01a0cabb-itsim`)                                                                                                                    |
| база слияния              | `0864423` (мерж PR #9)                                                                                                                                |
| `main` на момент проверки | `47b0896` (мерж PR #10, 21.10.2026 22:01)                                                                                                             |
| конфликтов                | **40 путей**: 37 × `packages/client/public/layers/avatar-v2/*.webp`, `tools/art/avatar-key.mjs`, `tools/art/avatar-v2/preview.mjs`, `preview-all.mjs` |
| статус GitHub             | `mergeable: CONFLICTING`, `mergeStateStatus: DIRTY`                                                                                                   |

Это не «две независимые фичи на одни файлы», а **две половины одного разбора
арт-пайплайна** от 23.09.2026: тулинг (этап 4a) уехал в PR #10, перекалиброванный
арт, манифест v2 и UI-блоки (этап 4b) — в PR #11
(`docs/ANALYSIS-2026-09-23.md` §7.1, §8). Обе половины писали одни и те же пути —
опубликованные webp и скрипты предпросмотра — потому что вторая переделывала
результат первой. Пока #10 лежал невлитым, пересечение не мешало; 21.10 его влили,
и пересечение стало конфликтом на каждый файл. Отсюда же и решение: брать сторону
#11, а не «смешивать» — это не конкурирующие правки, а новая версия того же
пайплайна поверх старой (см. §3).

Плюс один конфликт, которого git **не показал**: `packages/content/layers/avatar_manifest.json`
слился «чисто» и молча потерял правку PR #11 (см. §3).

## 3. Как разрешено слияние (ветка `arena/e4f67840-itsim`)

Сторона PR #11 взята на всех 40 конфликтах. Основание — не «она новее», а то,
что две версии несовместимы по смыслу, и клиент PR #11 рассчитан на свою:

- **`tools/art/avatar-key.mjs`.** В `main` — v4 с ручной таблицей `OVERRIDES`:
  38 магических констант вида `scale: 0.10, ay: 0.18` на слой. В PR #11 —
  геометрия: `bodyGeometry()` меряет манекен, `slotTargets()` даёт бокс слота,
  `placeFit()` заполняет его под потолком `MAX_STRETCH = 1.5`, а посадку меряет
  отдельный страж `check-placement.mjs`. Вторая версия измеряемая, первая — нет;
  именно это `docs/ANALYSIS-2026-09-23.md` §2.2(б) описал как «12 слоёв из 38
  годные».
- **37 webp.** Набор PR #11 перекалиброван (посадка, `faceClearance`, возврат
  тинтинга: слои отдаются шкалой серого, `tintSlot: hairColor` снова красит).
  Набор `main` — предокрашенный, то есть `tintFilter()` из клиента PR #11 по нему
  дал бы неверные цвета.
- **`preview.mjs` / `preview-all.mjs`.** Версия PR #11 берёт слои из `public/`,
  когда каталога сборки нет, и пишет в `artifacts/` (в git не попадает).

Что слияние принесло из `main` и пришлось убрать отдельно:

- `tools/art/avatar-v2/rebuild.sh` — 38 жёстко зашитых строк и `cd /home/user/Itsim`
  первой строкой; CLI у него уже не совпадает с новым `avatar-key.mjs` (нет
  `--body-master`), то есть скрипт нерабочий. Заменён `build.mjs` + `build.config.json`.
- `tools/art/avatar-v2/preview.png`, `preview-all.png` (2.8 МБ) — рендеры набора
  PR #10; пересобираются `npm run avatar:preview -w tools/art` в `artifacts/`.
- `1.png`, `2.png` (3.9 МБ) и `seesprite.tmp.mjs` в корне — удалены самим PR #11,
  `.gitignore` от этого защищает.

## 4. Что нашлось по ходу, кроме конфликта

1. **`npm test` на свежем клоне падал на 15 тестах сервера.** Корневой скрипт
   собирал только `@itsim/shared`, а серверные тесты импортируют `@itsim/content`,
   у которого `main`/`exports` смотрят в `dist/`. Ошибка —
   «Failed to resolve entry for package "@itsim/content"»: целиком падал
   `endgameContent.test.ts` и все 15 `payments.test.ts`. В песочницах агентов
   `dist` уже лежал от прошлых сборок, поэтому в отчётах было «400/400 зелёных».
   В CI тот же обрыв не проявлялся случайно: там до тестов успевает
   `lint:types`, а `tsc -p packages/content` эмитит `dist`. Починено: корневой
   `test` собирает content, в CI добавлен явный шаг сборки.
2. **42 МБ арт-исходников в git.** PR #10 внёс `tools/art/avatar-v2/masters/`
   (40 PNG, 39.08 МБ) и `layers/` (38 webp — побайтовый дубль `public/`), хотя
   решение «мастера вне git» зафиксировано 23.09 в
   `docs/QUESTIONS-2026-09-23.md` §M, а `.gitignore` PR #11 эти пути уже
   перечислял (на отслеживаемые файлы ignore не действует). Подтверждено
   пользователем 22.10 → `git rm -r --cached`, 78 путей, −40.3 МБ в чекауте.
   История не худеет. Как достать набор заново — `tools/art/avatar-v2/README.md`
   §«Где брать мастеров».
3. **`avatar:build` из клона не воспроизводим: нет `b9/bottom_chinos.png`.**
   `build.config.json` PR #11 ссылается на перерисованный мастер `b9/`, которого
   не было ни в PR #10, ни в git (он жил только в песочнице агента). Из 38
   мастеров в восстановленном наборе есть 37, поэтому сборка честно падает:
   `✗ нет 1 из 38 мастеров`. Гейты от этого не зависят: `avatar:check` мерит
   опубликованный набор (0 нарушений, 4 предупреждения-долга).
4. **Два поля финалов читались, но не писались никем.** `checkEndings` брал
   `player.leadership` и `player.mentoredJuniors`; ни один модуль их не
   записывает (проверено grep'ом по `packages/server` и `packages/shared`).
   Игра растит `softSkills.leadership.level` — его же меряет гейт CTO.
   `leadership` исправлен (§5), `mentoredJuniors` — нет: это недостающая
   механика, а не опечатка (см. `docs/TODO.md` §2).
5. **Коридор «CTO ≤ 35% за год» мерил пустоту.** На 365 днях ни один из 40
   агентов не избирается (0%), поэтому гейт не мог покраснеть ни при каком
   балансе. Измерение на двух годах: 40/40 избраны (медиана 390-й день), 40/40
   забрали финал (медиана 450-й).

### 5.2 В2: CTO — должность, а не финал (решение пользователя от 22.10.2026)

Разбор и четыре варианта — `docs/PROPOSALS-2026-09-27-endgame.md`. Выбран В2,
срок удержания 60 дней. Что изменилось:

| слой                                 | правка                                                                                                                               |
| ------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `shared/types`                       | `ctoSinceDay?: number` — день избрания                                                                                               |
| `shared/schemas`                     | `endings.cto.minDaysAsCto` (дефолт 60)                                                                                               |
| `shared/engine/endings.ts`           | `ctoTenureDays()`, `leadershipLevel()`, условие финала: репутация + лидерство + грейд + работа + срок                                |
| `shared/engine/migrations.ts`        | `CURRENT_STATE_VERSION = 4`, миграция `v4_cto_tenure`, санитизация срока в `normalizeState`                                          |
| `content/balance.json`               | `minDaysAsCto: 60`, подпись финала про отчёт, а не про день выборов                                                                  |
| `content/events/events_endgame.json` | +4 события CTO: `cto_first_board_report`, `cto_midnight_incident` (пул) и `cto_confidence_vote`, `cto_postmortem_board` (цепочечные) |
| `server/routes/game/ending.ts`       | победа пишет `ctoSinceDay`, не пишет `careerEnding`; `ctoHoldDays(content)`                                                          |
| `server/routes/game/day.ts`          | `loseCtoSeat()`: потеря работы снимает срок и возвращает грейд в `architect`                                                         |
| `client/screens/EndingView.tsx`      | строка «Срок в кресле CTO: X / 60 дн.» тем же движком, что считает доступность                                                       |
| `sim/simulate.ts`                    | срок удержания + двухлетний зонд (3 гейта: слой достижим, финал не выдаётся в день выборов, финалов не больше избраний)              |

Миграция v4 разбирает два случая по-разному: сидящему CTO (`grade === 'cto'` и
есть работа) финал `corporate_god` **снимается**, а день избрания
восстанавливается из `lastPromotionDay` — до v4 выборы ставили его сами, то
есть игрок не выбирал «закончить жизнь». Если кресла уже нет, финал остаётся:
снять его означало бы запереть игрока (`canStartNewLife` опирается на
`careerEnding`, а CTO-финал без работы недостижим).

Отступления от плана §4 в доке предложений (осознанные):

- ключ назван `minDaysAsCto`, а не `minDaysInGrade`: `minDaysInGrade` у
  карьерных гейтов уже означает «сколько дней в предыдущем грейде до ревью»,
  и тот же термин в двух смыслах — ловушка для следующего читателя;
- счётчика «проваленных отчётов борда» нет: отстранение идёт через уже
  существующий механизм (`jobWarnings` → увольнение → `loseCtoSeat`), а новый
  счётчик потребовал бы нового типа эффектов событий;
- `checkEndings` дополнительно требует наличия работы: без этого уволенный CTO
  досиживал бы 60 дней безработным и забирал финал, ни дня не руководя.

> Изометрия — это «мир» игры: с 23.09.2026 в ней остался только офис. Плоская
> комната и фигура — [design.md](design.md) §12.5; хром поверх —
> [design-system.md](design-system.md).

![Восемь iso-комнат по уровням жилья — так комната выглядела до 23.09.2026 (генератор удалён)](assets/iso-rooms.png)

Движок рисует офис компании (`IsoOffice`) и даёт перекраску HUD-портрета
(`PlayerPortrait`); список спрайтов и хук — `iso/manifest.ts`
(`useIsoManifest`, `useSpriteVariants`).

**Комната игрока с 23.09.2026 плоская и слоистая** — её рисует
`RoomRenderer` поверх `room_manifest.json`, а персонаж в ней стоит
полнофигурным `ProceduralAvatar` из `avatar_manifest.json` (webp 500×760).
Причина не во вкусе: пока комната была iso-диорамой, 38 откалиброванных
слоёв одежды не рисовались нигде — `BaseLook` iso-персонажа знает только
`top` и `hair`, слота `bottom` в нём нет вовсе, а четыре худи схлопываются в
один спрайт-силуэт (`iso/palette.ts`, `TOP_STYLE`).

Ручные цвета гардероба (тон кожи, волосы, борода) проходят через
`lookTintOverrides` + `tintFromHex` и перекрывают палитру генетики — на всех
четырёх поверхностях сразу (комната, профиль, шаринг, редактор), потому что
фильтр считается в одном месте — в `buildLayerStack`. Ряды «цвет верха / низа /
обуви» при этом iso-специфичны и остаются в UI с подписью: у плоских webp-слоёв
`top`/`bottom` нет `tintSlot`, а grayscale-мастеров для них не нарисовано, так
что перекрасить их в плоском стеке движок не может (план —
[TODO.md](TODO.md) §2).

Карточка шеринга — тоже плоский стек: `room/ShareCard.tsx` берёт слои из
`room/shareScene.ts`, который складывает их ровно тем же `buildLayerStack` и с
теми же долями кадра, что и `RoomRenderer` (карточка обязана совпадать с игрой
кадр в кадр — в этом единственный смысл её существовать).

Удалено 23.09.2026 (пункт B в
[QUESTIONS-2026-09-23.md](QUESTIONS-2026-09-23.md), решение — «признать iso
осознанным выбором для офиса и погрудья, комнату больше не держать в двух
движках»):

| ------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------- |
| React-компонент `IsoRoom` и iso-пейнтер `iso/canvas.ts` (`drawIsoRoom`) — сняты вместе с переходом на плоский стек | `RoomRenderer` + `room/shareScene.ts`                                                                                             |

| `petLook` + `DEFAULT_COAT` в `iso/palette.ts`                                                                      | вид питомца в комнате берётся из `room_manifest` (слой `pet`, состояние `petFed`)                                                 |
| 14 тестов `describe('buildRoomScene')` в `iso/__tests__/scenes.test.ts`                                            | файл переименован в `officeScene.test.ts`; инварианты аллокатора (мебель не наезжает, есть где стоять команде) остались при офисе |

Скорлупа (`iso/shell.ts`), геометрия (`iso/geometry.ts`), аллокатор
(`iso/allocator.ts`), палитра людей (`iso/palette.ts`) и конвейер нарезки
(`tools/isogen`) остаются: они нужны офису и погрудным бюстам. Ниже — как
устроен конвейер и где что править.

## 1. Проекция

Дметрия 2:1, тайл `64×32`, высота стены `144`.

```
screenX = origin.x + (gx - gy) * 32
screenY = origin.y + (gx + gy) * 16
origin  = { x: MARGIN.x·k + depth * 32, y: MARGIN.top·k + wallH }
```

Сетка вдвое крупнее «классических» 32×16 намеренно: исходные листы приходят
разрешением 130–350 px на объект, и ужать их до 26×46 (как было) значит выкинуть
24 пикселя из 25. При тайле 64 персонаж живёт в ~92 px, лицо и одежда остаются
читаемыми, а на телефоне с DPR 2–3 комната попадает почти пиксель-в-пиксель.
Смещения в коде сцены по-прежнему написаны в единицах 32-пиксельного тайла и
умножаются на `unit(tile) = tile.w / 32`.

Порядок отрисовки — сортировка по `gx + gy` (`layout()` в `components/iso/geometry.ts`).
Напольный спрайт «стоит» нижним углом в клетке `(gx + w, gy + d)`, стены получают
глубину `-1000`, плоские наклейки (ковёр, миска) — смещение `-0.5`, чтобы не спорить
с мебелью в той же клетке. Крупные предметы нельзя ставить в крайние клетки: их
основание вылезет за пол.

## 2. Библиотека спрайтов

`packages/client/public/iso/` — 108 PNG плюс `manifest.json`:

```jsonc
{
  "tile": { "w": 32, "h": 16, "wallH": 72 },
  "sprites": {
    "bed_single": { "file": "bed_single.png", "w": 96, "h": 72, "kind": "floor", "tiles": [2, 3] },
    "char_a03": {
      "file": "char_a03.png",
      "w": 52,
      "h": 92,
      "kind": "char",
      "roles": { "skin": ["#6b4a35", "#a9714f", "#d3a07a"], "hair": ["#2b2118", "#4a382a"] },
    },
    "window": { "file": "window.png", "w": 98, "h": 134, "kind": "wall", "tilesW": 3, "face": "left" },
  },
}
```

`roles` — это рампы: исходные hex спрайта, отсортированные по яркости. Рантайм
подменяет их на рампу целевого цвета (`components/iso/recolor.ts`), растягивая её
между `#1e2430` и `#fff6e2`. Замена идёт по точному RGB, поэтому цветовые роли
извлекаются **до** квантования палитры, а обводка и альфа не трогаются.

Роли персонажа: `skin`, `hair`, `top`, `bottom`, `shoes`. Роль животного: `coat`.
На 19 базовых силуэтах это даёт ≈547 000 внешностей.

## 3. Конвейер ассетов (`tools/isogen`)

```bash
# 1) нарезать сгенерированный лист на отдельные спрайты
node tools/isogen/slice.mjs tools/isogen/raw/pets2.png /tmp/iso/slices --min 700 --gap 8
# 2) прописать нарезки в tools/isogen/catalogue.json (id, kind, tiles)
# 3) собрать public/iso + manifest.json
node tools/isogen/build.mjs /tmp/iso/slices
# 4) посмотреть результат офлайн, без браузера
npx tsx tools/isogen/preview.ts        /tmp/iso/rooms.png  --scale 2 --cols 4
npx tsx tools/isogen/preview-office.ts /tmp/iso/office.png --scale 2
npx tsx tools/isogen/preview-people.ts /tmp/iso/people.png --count 36 --scale 3 --cols 12
```

`build.mjs` делает де-фриндж (магента-фон), тримминг, ресайз под сетку (ядро
`lanczos3`, а не `nearest`: при уменьшении в 3 раза «ближайший сосед» рвёт обводки
и глаза), квантование палитры в 64 цвета и извлечение цветовых ролей.

Цветовые варианты одной вещи не рисуются заново, а получаются из базового спрайта:
`node tools/isogen/tint.mjs <in.png> <out.png> <targetHex>` поворачивает оттенок
доминирующего цвета в целевой (обводка, блики и структура затенения остаются
нетронутыми). Так из `rug_rolled` получились `rug_moss` (#7fae7a) и `rug_sand`
(#cfa06a), из `armchair` — `armchair_clay` (#c2565a) и `armchair_teal` (#3f8a94);
раскладка комнаты выбирает цветовую семью по своему seed.

### Ориентация настенных спрайтов

Картина на правой стене должна «падать» вправо, на левой — влево. Листы приходят
вперемешку, и повешенная не на ту стену картина выглядит приклеенной торцом.
Поэтому `build.mjs` измеряет наклон верхней кромки спрайта (медиана попарных
наклонов, крайняя восьмая ширины отбрасывается — там шторы и провода) и пишет в
манифест `face: "left" | "right" | "flat"`:

- `left`/`right` — рисунок отзеркаливается, когда его вешают на другую стену;
- `flat` — рисунок сделан анфас, и рендер **скашивает** его в плоскость стены
  (`spriteTransform` → `skewY(±26.565°)`, тот же наклон 1:2, что и у проекции;
  в офлайн-превью — `sharp.affine`).

Классификация ролей работает по гистограмме: пиксели темнее `lum < 24` считаются
обводкой и пропускаются; для остальных копится распределение по четырём полосам
высоты (голова / торс / ноги / обувь). Цвет, размазанный по всей фигуре
(`focus < 0.6`), — структурный, он не перекрашивается. Кожа отделяется по оттенку
(`r > g ≥ b`, hue 8–48), тёмная причёска — по правилу «верхняя полоса и заметно
темнее самой светлой кожи», бежевый свитер — по доле пикселей в торсе.

Промпт, которым генерятся листы, лежит в комментарии к `tools/isogen/catalogue.json`;
главное в нём — «2:1 dimetric isometric projection, all objects share the exact same
viewing angle and scale, solid flat magenta background #ff00ff».

## 4. Что из чего собирается

| Слой      | Файл                                          | Правила                                                                                                                                      |
| --------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Комната   | ~~`iso/scene.ts`~~ → `components/room/`       | с 23.09.2026 плоская: слои `room_manifest.json` + `buildLayerStack`; уровень жилья выбирает набор доступных записей, а не размер 6×6 … 10×9  |
| Отделка   | `shared/engine/isoFinishes.ts`                | 12 красок × 10 полов с паттернами; `tiers` ограничивают выбор по жилью, `null` = авто по seed. Пишется в `player.room.paint/floor` и валидируется сервером; рисует их только офис и сейвы, собранные до 23.09.2026 |
| Внешность | `shared/engine/isoLook.ts` + `iso/palette.ts` | 6 тонов кожи, 10 цветов волос, 12 верха, 8 низа, 5 обуви; выбор игрока перекрывает seed. Работает для iso-бюста и офиса; плоская фигура красит `body`/`hair`/`beard` через `tintSlot` |
| Питомец   | ~~`iso/scene.ts`~~ → `room_manifest` (`pet`)  | в iso-комнате был `sleep`/`eat`/`play` + миска; в плоской — слой из манифеста, состояние `petFedToday`                                       |
| Офис      | `iso/office.ts`                               | garage / cowork / product / corp, 7×6 … 11×9, ночная палитра, коллеги из того же генератора людей                                            |

Цвета внешности меняются бесплатно (`customize_avatar` на сервере принимает
`skin/hairColor/topColor/bottomColor/shoeColor` без списания денег и валидирует hex
по палитре), перекраска стен и пола стоит `REPAINT_COST = 500`.

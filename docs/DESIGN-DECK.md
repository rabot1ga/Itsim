# DESIGN-DECK: «Колода» — редизайн UX/UI и цикла дня

Статус: выбран игроком 28.10.2026 (вариант C из docs/PROPOSALS-2026-10-28-redesign.md).
Принцип: **один экран, один жест, одно решение за раз**. Сервер (день, события,
карьера, интервью, питомец) меняется точечно; клиент переписывается под стек
карточек. Наработки аудита A–I не выбрасываются — они становятся карточками.

## 1. Три закона

1. **Всё — карточка.** Действие, событие, выбор, итог, даже ошибка — карточки
   одного стека. Никаких «плиток в три ряда» и меню-деревьев.
2. **Жест = решение.** Свайп вправо — «да/сделать», влево — «нет/пропустить»,
   тап по варианту — когда выборов больше двух. Под каждой карточкой те же
   действия кнопками (доступность + e2e).
3. **Метры видны всегда.** Деньги / энергия / настроение / здоровье — одна
   компактная строка над стеком (A из аудита); множитель опыта — подписью.

## 2. Экран

```
┌────────────────────────────┐
│ 10 300 ₽   ⚡ 7/16  ×1.2   │  метры (всегда)
│ 😊 ████████░░  ❤ ██████░░  │
├────────────────────────────┤
│        ┌──────────┐        │
│        │ карточка │        │  стек: верхняя — решение
│        │  стека   │        │
│        └──────────┘        │
│      ◀ пропустить | сделать ▶│  кнопки-дублёры жеста
│        · · ● ·             │  индикатор: карточек осталось
├────────────────────────────┤
│  [Сегодня]        [Архив]  │  2 контрола вместо таббара
└────────────────────────────┘
```

- **Таббара больше нет.** Нижняя панель: «Сегодня» (стек) и «Архив»
  (шторка со всеми экранами: Работа, Развитие, Прогресс, Дом, Питомец,
  Магазин, Майнинг, Друзья, Настройки, Профиль).
- История стека: перевёрнутая карточка-результат (followup + дельты) →
  «Дальше».

## 3. День = три отделения стека

1. **Утро.** Карточка-заставка дня (дата, стоимость дня, крючок G одной
   строкой). Затем **карточки действий** — план дня: работа, учёба, быт,
   отдых. Свайп вправо = выполнить (энергия/деньги списываются, награда
   показана на карточке заранее), влево = пропустить. Гарантированные карты:
   «Первые шаги» (B, первые дни), «Почти готово» (G), «Оффер сгорает»,
   «Повезёт» (F, серия отказов — метка на карточке отклика).
2. **День.** Событие (`activeEvent`) — карточка с2–4 вариантами (текущий
   EventCard переезжает в стек как есть). Результат — перевёрнутая карточка
   (`EventOutcomeCard`). Событие может прилететь из действия — тогда оно
   встаёт в стек следующим.
3. **Вечер.** Последняя карточка стека — «Завершить день» (свайп вправо /
   Enter). Итог дня — `DaySummaryCard` (уже карточка), после «Дальше» —
   новое утро.

Приоритеты не меняются: `daySummary > activeEvent > стек`.

## 4. Карточки действия — предмет редизайна

```
┌──────────────────────┐
│ [иконка]  Учёба      │
│ Курс по TypeScript   │
│ −2 ⚡   +XP ×1.2     │   награда/цена видны ДО решения
│ «Дороже курс — …»    │   flavor-строка
├──────────────────────┤
│  «пропустить» «сделать»│
└──────────────────────┘
```

- Каждая карточка: иконка, заголовок, цена (энергия/деньги), награда
  (XP/деньги/метры), одна строка характера (флейвор из контента).
- Свайпы анимированы (улетает вбок), метры пружинят при дельтах, haptic.

## 5. Механики-дельты (этапы 3–4)

- **Колода формируется, а не собирается вручную.** Утренний стек: 3–5
  карточек по фазе игры + гарантии (крючки G/B/F). «Ещё» — карточка-колодца
  (дотянуть ещё действие), когда энергия остаётся.
- **Модификаторы карт.** Перки/архетипы/предметы открывают **новые варианты
  ответа** на существующих карточках (не «+5% к цифре», а новый выбор:
  «Делегировать задачу стажёру» появляется на карточке работы после перка
  «Наставник»). Это и есть смена механики: прогрессия = глубина колоды.
- **Неделя = «сезон»**: спринт/зарплата/ревью — карточки-события недели
  (текущие SprintCard и CareerPressureCard перетекают в стек).

## 6. Миграция (что с чем)

| Было | Стало |
| --- | --- |
| DayView (плитки, двери, чек-листы) | DeckView: стек карточек дня |
| DayEndDock | карточка «Завершить день» последней в стеке |
| Таббар (4 таба) | «Сегодня» + «Архив»-шторка |
| MorningBrief (G), FirstSteps (B) | карточки стека |
| EventCard / EventOutcomeCard / DaySummaryCard | как есть, внутри стека |
| ActionGrid / NavLinks | карточки действий / пункты архива |
| SkillsView / CareerView / ProgressView / … | экраны «Архива» (панели), не переписываются |
| `.story-card` (e2e-контракт) | сохраняется ТОЛЬКО за событиями; карточки стека — свой класс `deck-card` |

## 7. Этапы

1. **Стек дня** — DeckCard + DeckView + метры + «Архив»-шторка; DayView
   уходит в архив как «Обзор дня» (или удаляется); e2e: `deck.spec.ts`,
   навигация через архив; спеки переписываются точечно.
2. **Контент-карточки** — интервью-квиз и фриланс/проекты как карточки;
   онбординг = первые3 карточки стека; крючки/пити как гарантии стека.
3. **Механики-дельты** — модификаторы карт (перки/предметы = новые варианты),
   «сезон» недели.
4. **Полировка** — motion-система, звуки/хаптика жестов, темы, пустые
   состояния, a11y-проход.

## 8. Ограничения и риски

- Telegram Mini App: свайпы не должны конфликтовать со свайпами Telegram
  (вертикальные — ок, горизонтальные — наши); кнопки-дублёры обязательны.
- 320px: карточка — единственный герой, метры — одна строка.
- Стек не должен стать «ещё одним списком»: лимит 5 карточек утреннего плана,
  остальное — «ещё».
- e2e: `.story-card:not(.day-summary-card)` сохраняется контрактом.

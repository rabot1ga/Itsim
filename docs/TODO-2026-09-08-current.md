## 3. Противоречия, найденные в ходе ревизии (2026-09-08)

### 3.1 Дубль «Магазин» в MORE (исправлено)

В `GameScreen.tsx` MORE содержал `{ view: 'shop', … }`, тогда как «Магазин»
уже в нижних табах. Пользователь видел одну и ту же точку входа дважды.
**Исправлено** в текущей итерации: `shop` убран из MORE.

### 3.2 NPC-аватары не подключены в OfficeView (исправлено)

`OfficeView.tsx` показывал команду через эмодзи `🧑‍💼👩‍💻😠`, хотя
загружены 5 портретов в `public/art/npcs/`. **Исправлено**: `OfficeView`
теперь рендерит `<img src="/art/npcs/…">` с fallback на эмодзи.

### 3.3 LeaderboardView — RANK_TONE undefined для ранга 4+ (исправлено)

Старый код использовал `RANK_TONE[row.rank - 1] ?? 'text-ink-500 …'`, что
падало в дефолт начиная с 4-й строки, но тип `string[]` это не отражал.
**Исправлено**: `RANK_TONE` теперь `Record<number, string>` с явным
`DEFAULT_RANK_TONE`.

### 3.4 README vs реальность — «7-й таб Топ» (частично)

README утверждает, что «Топ» — седьмая вкладка, но в `GameScreen.tsx` это
пункт MORE. **Частично решено** в UI 06: «Топ» — в MORE, как «Дом»,
«Цели», «Офис», «Профиль». README §«Экраны» обновлён в PR #7, но
формулировка про «7-й таб» осталась в §«Клиент и визуал» — нужен явный
комментарий.

### 3.5 ROADMAP-2026-09-08 устарел

Файл `docs/roadmap-2026-09-08.md` говорит «P0 всё, P1.1–P1.3 сделаны;
дальше P1.4 (коллекции-сеты дома)» — но с тех пор:
- P1.5 «Профиль игрока» частично сделан (`ProfileView` со статистикой и
  переходами; нет кошелька-настроек).
- P1.6 «Магазин на видное место» — частично (нет кнопки-«кошелька» в HUD).
- P1.7 «Разбить game.ts» — **не сделано**, файл всё ещё 1.9k строк.
- P1.8 «Postgres» — **не сделано**.

**Решение**: `roadmap-2026-09-08.md` остаётся как история; см. §4
настоящего документа за актуальным планом.

### 3.6 Hardcoded HOUSING в ShopView (открыто)

`ShopView.tsx` дублирует массив `HOUSING`, хотя полный источник —
`balance.housing[]` (5 уровней с `energyBonus`, `motivationBonus`,
`reputationBonus`, `incomeGateMult`, `saveMult`, `saveStreakDays`).
Источник истины — контент, как и для всего остального.

### 3.7 SHOP_CATEGORIES в shopCatalogue.ts (открыто)

`SHOP_CATEGORIES` хардкоден в `screens/shopCatalogue.ts`, но `items.json`
содержит поле `type`, а категоризация делается по нему. Категории должны
приходить из контента или хотя бы — раздел «equipment»/«home»/«pets»/
«courses» — следовать типам в `items.json`.

### 3.8 Отсутствуют экраны Mining и Pet

Майнинг-блок встроен в DayView, питомец — только кнопка «Покормить».
Отдельных экранов для настройки фермы и взаимодействия с питомцем нет, в
то время как в `MORE` есть место. **Решение**: добавить вторичные экраны
«Майнинг» и «Питомец» (P1.9 в плане ниже).

### 3.9 Wallet/NFT-кошелёк — не на виду

Роудмап P1.6 и P2.1 обещают «кнопку-кошелёк в HUD» и «профиль-кошелёк».
Сейчас NFT-инвентарь доступен только через `RoomView` →
`loadNft()` → никуда. **Решение**: добавить «Кошелёк» как пункт MORE
после «Дом» (P1.10).

### 3.10 Финалы exit/free_artist/teacher (открыто)

`balance.endings` сейчас содержит только `burnoutDays: 7` и
`brokeDaysToQuit: 15` — это условия для терминальных финалов, а не
описания «позитивных» финалов. В ТЗ/README упоминаются 6 финалов, но
в цикле реализованы только `burnout` и `left_it`. **Решение**: расширить
`balance.endings` и реализовать проверки + экран.

### 3.11 profile-card / miniapp-chrome / reference-* — устаревший нейминг

В `index.css` остаются CSS-классы вроде `miniapp-chrome`, `reference-app`,
`reference-screen-title` от предыдущей итерации, не используемые
финальным UI 06/07. **Решение**: точечная чистка, чтобы не сломать
визуальные тесты.

### P1.10 WalletView (планируется)
NFT-инвентарь, привязка кошелька, бейджи, синхронизация с

### P1.11 PetView (планируется)
Питомец: экипировка аксессуарами, статус, эффекты. Доступ: MORE →
«Питомец».

### P1.12 Полная реализация финалов (планируется)
- `exit` (стартап ≥ 100 млн): разблокируется при `reputation ≥ 80` и
  `money ≥ 100_000_000` + действие `start_company`. Награда: бейдж +
  удвоенный `metaXpMult`.
- `free_artist`: при `reputation ≥ 40`, `money < 1_000_000` и
  `grade ≥ senior` + действие `go_freelance`. Награда: «скин-фулстек» в
  гардероб.
- `teacher`: при `reputation ≥ 60`, `mentoredCount ≥ 50`. Награда: +25% к
  социальному XP навсегда.

### P1.13 Refactor: вынести HOUSING и SHOP_CATEGORIES в контент (планируется)
- `HOUSING` из `ShopView.tsx` → `GET /api/content/housing` или
  `balance.housing[]` (уже есть).
- `SHOP_CATEGORIES` из `shopCatalogue.ts` → `balance.shopCategories[]` или
  `items.json` (`type` × порядок).

## 5. Не входит в ближний план

- **PostgreSQL + Prisma** — интерфейс хранилища уже узкий, миграции
  сейвов есть. Переезд стоит делать вместе с решением про хостинг.
- **`npm run format`** по всей базе — в CI `continue-on-error`, чтобы не
  смешивать переформатирование с содержательными правками.
- **Реальный Solana-провайдер** (Helius RPC) вместо `MockNftProvider` —
  роадмап P2.2; требует кошельков от живых игроков.
- **i18n (EN)** — тексты в коде, не вынесены; нужна инфраструктура
  словарей.
- **Звуки** и **режим высокого контраста**.

# P2.4: Серверный RNG везде, где влияет на баланс — аудит и миграционный план (23.10.2026)

Статус: **реализовано.** Задача из TODO §4: «события всё ещё используют
клиентский seed, нужен миграционный план». Аудит показал: исходная посылка
устарела, но нашлись две настоящие дыры — предсказуемые сиды и
невоспроизводимый `Math.random`.

## Аудит (список расхождений)

1. **«События используют клиентский seed» — неверно (текст TODO устарел).**
   Клиент не катает баланс вообще: в `packages/client/src` нет ни `Math.random`,
   ни `seededRng`. События, увольнения, фриланс-биды, авто-собеседования,
   вариации выплат, NPC-встречи, траты, выборы CTO и цепочки событий катает
   **сервер** в `routes/game/{day,actions,ending}.ts`, клиент только вызывает
   `POST /api/game/*` и рисует ответ. Никакого `state.seed` в сейве не существует.
2. **Настоящая дыра А — предсказуемые детерминированные сиды.** Вопросы
   интервью катаются с ключом `${userId}:interview:${companyId}:${interviewDay}`
   (`routes/game/interview.ts`), челлендж дня — `${userId}:challenge:${currentDay}`
   (`routes/game/_day.ts`). Формула сида публична, банк вопросов — публичный
   контент: игрок может пересчитать вопросы/челлендж офлайн и подготовиться.
3. **Настоящая дыра Б — невоспроизводимый `Math.random`.** Все броски баланса
   идут через обёртку `rng()` (= `Math.random`) и `rollInterview(chance,
   Math.random)`: спорный бросок (увольнение, выборы) нельзя пересоздать при
   разборе жалобы, а тесты вынуждены мокать глобальный `Math.random`.
4. **Генетика**, на которую ссылался TODO как на «серверный RNG», удалена
   фазой 2b редизайна — упоминание в TODO устарело.

Чего дырой **нет**: клиент не может ни подсунуть seed, ни переотправить
«выгодный» результат — `saveState` вызывается только серверной логикой,
готовый сейв из сети не принимается (единственный вход — `GET /api/game/state`).

## Миграционный план

1. **`state.rngSalt`** (hex 16 байт) + **`state.rngSeq`** (счётчик бросков) —
   поля сейва, версия **v6** (`v6_rng_salt`): соль генерирует сервер, клиент
   её не видит — `stripInternal()` (тот же механизм, что для `_idem`) вырезает
   оба поля из каждого ответа. `createNewPlayer()` ставит поля сразу,
   `normalizeState()` достраивает их для любых сейвов (страховка).
2. **Единый поток бросков** `rngStream(state)`: каждый бросок —
   `seededRng(\`${telegramId}:${rngSalt}:${rngSeq++}\`)`. Свойства:
   клиент не влияет; путь полностью воспроизводим (можно пересчитать день по
   сейву, соль секретна от игрока); повтор/перезапрос не даёт «перебросить» —
   счётчик монотонен. Все точки `rng()`/`Math.random` в балансе переведены на
   поток: `advanceDay` (увольнения, биды, авто-собесы, события), `actions`
   (вариации выплат, NPC, траты), `event-choice` (шанс цепочки), `ending.ctoElection`.
3. **Предсказуемые сиды** (дыра А) получают соль:
   `${userId}:${rngSalt}:challenge:${day}` и
   `${userId}:${rngSalt}:interview:${companyId}:${interviewDay}` — офлайн-подготовка
   больше невозможна; между игроками вопросы по-прежнему независимы.
4. **Тестовый сейм** — `__setRngFactoryForTests()` в `routes/game/shared.ts`
   (вместо моков глобального `Math.random`): тесты задают поток явно.
5. **Баланс не меняется**: распределения и формулы те же, `seededRng`
   равномерен; симулятор (собственный LCG с сидом прогона) не тронут.

Совместимость: миграция v6 добавляет поля к любому сейву, старые сейвы
читаются и перезаписываются штатно; восстановление из бэкапа без соли
получает новую (брошки прошлых дней не пересчитать — они остались в логах
сообщений).

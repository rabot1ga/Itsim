# Редизайн комнаты и снятие пиксельной идентичности (22.10.2026)

Статус: **принято, фаза 1 (комната) в работе; фаза 2 (removal) — следующим заходом;
фаза 3 (офис) — отдельный PR.**

## Решение (ask_user 22.10.2026)

- Вариант **B**: комната — карточка случайного события (баннер-иллюстрация +
  копи + строки-действия), в сцене один постоянный протагонист story-v1/финалов;
  кастомизации нет, значит «пиксельной идентичности» нет.
- **4 тира** прогресса: start → cozy → work → dream.
- Пиксельная идентичность убирается **полностью**: генетика (визуальные
  трейты), гардероб, слои/манифест аватара, dev-карточка, NFT-мок минта;
  сейв-миграция v5.
- Офис (iso, экран «Работа») — **отдельным PR** тем же карточным стилем.

## Расхождения, которые закрыло решение

- Комната/«Дом» была конструктором: `useRoomScene` + `RoomRenderer` +
  `ProceduralAvatar` + слои аватара + редактор + шаринг-карточка. Визуально —
  «леко» из пиксельных кусков, три языка арта (плоский стек / iso / 32×32),
  см. `docs/QUESTIONS-2026-09-23.md` §J.
- Пиксельная идентичность тянула за собой: визуальную генетику в онбординге,
  гардероб, tint-ряды, NFT-мок и кошелёк на «Доме», e2e-локаторы по
  `/layers/room/`, dev-карточку «Пиксельная идентичность».
- Аватар-v2 требовал вечного арт-долга: 40 МБ мастеров вне git, предупреждения
  стража, перерисовки поз (PR #14 закрыл предупреждения, но системно боль
  осталась).

## Фаза 1 — комната как карточка события (этот PR)

- `public/art/room/{start,cozy,work,dream}.webp` — 512×384 (4:3, без кропа в
  `.story-card-art`), один арт-прогон в палитре игры, серия с общими костями
  комнаты и протагонистом; provenance — в README каталога.
- `packages/client/src/lib/roomArt.ts`: `roomTierOf(grade)` (intern/junior →
  start, middle → cozy, senior → work, teamlead+ → dream), `roomArtwork`,
  `ROOM_TIER_META`. Без нового состояния и миграций.
- `RoomView.tsx`: `<section class="story-card">` с баннером тира и строками-
  зонами поверх общего каталога действий (`rest_sleep`, `rest_walk`,
  `rest_hobby`, `work_task` (нужна работа), `study_book`, `feed_pet` (если есть
  питомец)); чипы эффектов — из `ACTIONS`, как у событий. Навигация между
  вкладками из комнаты не нужна: все зоны — прямые действия.
- `HomeRoomCard.tsx`: миниатюра тира (`.room-thumb`) + настроение на «Главной».
- Удалён конструктор комнаты: `RoomRenderer`, `RoomEditor`, `ShareCard`,
  `shareScene`, `useRoomScene`, `PixelIdentity`, `PixelAvatar`, `pixelAvatar`,
  тест shareScene. e2e `layout.spec.ts` переведён с `/layers/room/` на
  `/art/room/`.
- Оставлено до фазы 2: `Wardrobe` (ProfileView), `ProceduralAvatar` +
  `OfficeRenderer` + `layers` (офис), `PlayerPortrait`, стек аватара в контенте
  и генетика, кошелёк/NFT-блок на «Доме» (перенесён в новый RoomView как есть).

## Фаза 2 — снятие идентичности (следующий заход)

Удалить: `PlayerPortrait`, `Wardrobe`, `ProceduralAvatar`, `OfficeRenderer`,
`layers`, `useLayerContent`, стек аватара (`packages/content/layers/*`,
`avatar_manifest.json`, tint-конфиг), визуальные трейты генетики в онбординге и
`PlayerState.genetics/avatar`, NFT-мок (`nftProvider`, inventory, кошелёк на
«Доме», cross-collections), инструменты `tools/art/avatar-v2` + скрипты
`avatar:*` + шаг CI. Миграция сейва **v5**: дроп `genetics`/`avatar`/визуальных
полей (поля никогда не влияли на баланс, кроме NFT-мока). Тесты: переписать
`avatarLayers`/`playerPortrait` на тесты комнаты/`tint`-free онбординга; e2e —
онбординг без шага внешности.

## Фаза 3 — офис тем же стилем (отдельный PR)

Экран «Работа» = карточка события с баннером-сценой офиса (тир по компании/
грейду: опенспейс → кабинет → свой этаж), строки — рабочие действия; iso-стек
удаляется вместе с фазой 3.

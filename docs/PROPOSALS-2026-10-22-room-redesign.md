# Редизайн комнаты и снятие пиксельной идентичности (22.10.2026)

Статус: **принято; фазы 1 (комната) и 2 (профиль-карточка + полное снятие
идентичности, миграция v5) выполнены 22.10.2026; фаза 3 (офис тем же карточным
стилем) — отдельный PR.**

## Решение (ask_user 22.10.2026)

- Вариант **B**: комната — карточка случайного события (баннер-иллюстрация +
  копи + строки-действия), в сцене один постоянный протагонист story-v1/финалов;
  кастомизации нет, значит «пиксельной идентичности» нет.
- **4 тира** прогресса: start → cozy → work → dream.
- Пиксельная идентичность убирается **полностью**: генетика (визуальные
  трейты), гардероб, слои/манифест аватара, dev-карточка, NFT-мок минта;
  сейв-миграция v5.
- Офис (iso, экран «Работа») — **отдельным PR** тем же карточным стилем.

## Расхождения, которые закрыло решение

- Комната/«Дом» была конструктором: `useRoomScene` + `RoomRenderer` +
  `ProceduralAvatar` + слои аватара + редактор + шаринг-карточка. Визуально —
  «леко» из пиксельных кусков, три языка арта (плоский стек / iso / 32×32),
  см. `docs/QUESTIONS-2026-09-23.md` §J.
- Пиксельная идентичность тянула за собой: визуальную генетику в онбординге,
  гардероб, tint-ряды, NFT-мок и кошелёк на «Доме», e2e-локаторы по
  `/layers/room/`, dev-карточку «Пиксельная идентичность».
- Аватар-v2 требовал вечного арт-долга: 40 МБ мастеров вне git, предупреждения
  стража, перерисовки поз (PR #14 закрыл предупреждения, но системно боль
  осталась).

  `.story-card-art`), один арт-прогон в палитре игры, серия с общими костями
  комнаты и протагонистом; provenance — в README каталога.

- `RoomView.tsx`: `<section class="story-card">` с баннером тира и строками-
  зонами поверх общего каталога действий (`rest_sleep`, `rest_walk`,

  питомец)); чипы эффектов — из `ACTIONS`, как у событий. Навигация между
  вкладками из комнаты не нужна: все зоны — прямые действия.
- `HomeRoomCard.tsx`: миниатюра тира (`.room-thumb`) + настроение на «Главной».
- Удалён конструктор комнаты: `RoomRenderer`, `RoomEditor`, `ShareCard`,

## Фаза 3 — офис тем же стилем (в работе 22.10.2026)

Экран «Мой офис» = карточка события с баннером-сценой офиса (лестница тира:
опенспейс → кабинет → свой этаж → верхний этаж), строки — рабочие действия
общего каталога; iso-стек сцены удаляется.

### Аудит перед правками (список расхождений)

1. **IsoOffice — последняя «мультяшная» сцена.** После редизайна комнаты и
   профиля офис остался единственный экраном с процедурной iso-сценой
   (`components/iso/`: IsoOffice, office, allocator, geometry, shell, recolor,
   manifest, palette, officeMood — ~1300 строк) и не подходит карточному
   языку остальной игры.
2. **IsoIcon ≠ iso-стек.** `components/iso/IsoIcon.tsx` — просто `<img>` на
   `/iso/<sprite>.png`: им нарисованы товары в «Магазине» и жильё. Это живой
   хром (как HUD PixelIcon) — остаётся вместе со спрайтами `public/iso/`.
3. **shared `isoLook`/`isoFinishes` уже мёртвы**: экспортуются из
   `engine/index.ts`, но никто не импортирует (клиентская сцена держала свою
   `palette.ts`). Удаляются вместе с фазой 3.
4. **`useRenderMode`** (pixelated/auto) использовался только IsoOffice —
   удаляется.
5. **officeMood** — честная логика настроения дня (grade/company/energy/
   motivation/relationships) — остаётся, переезжает в `lib/officeMood.ts`
   и показывается строкой в карточке.
6. **Тесты**: `iso/__tests__/officeScene.test.ts` (генератор сцены) заменяется
   на `officeArt.test.ts`; фетч-мок `/iso/manifest.json` в `app.smoke`/`roomCard`
   был нужен только сцене — вычищается; e2e-спеки офис-сцену не трогали
   (overflow.spec упоминает лишь плитку «Офис» в меню).

### Дизайн (к карточке комнаты)

- Баннер `/art/office/<тир>.webp` — та же серия, что `art/room/`: пиксель-арт
  в палитре игры, 512×384 WebP q82, протагонист story-v1, «одни кости»: стол
  героя центр-право, окно с городом, статус растёт по тиру.
- Тир = прогресс грейда, **та же лестница, что у комнаты**
  (`roomTierOf` → start/cozy/work/dream ↔ openspace/cabinet/floor/tower):
  intern/junior → опенспейс (ряды столов), middle → кабинет (стеклянный угол
  команды), senior → свой этаж (переговорная + вид), teamlead+ → верхний этаж
  (панорама, угол стола). Компания остаётся в kicker (название + размер).
- Строки действий — `story-choice` как в RoomView (work_task / work_overtime /
  networking), команда — карточки NPC ниже (как есть).
- Маппинг «по компании» (4 размера) отклонён: смена компании уже даёт смену
  названия/размера в kicker, а визуальная лестница прогресса — то, что игрок
  читает как рост (как комната).

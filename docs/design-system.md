## 1. Принципы

Пять правил, которым подчиняется **любой** интерактив. Если новый элемент
им противоречит — он неправильный.

1. **Один золотой акцент на экран.** `gold` значит «здесь действие». Второй
   золотой элемент — лишний. Всё остальное — приглушённое (`ink`, `wood`,
   `sky`); состояния — `moss` / `ochre` / `clay` по смыслу.
2. **Один CTA на экран.** Кнопка `primary` (золотая) — одна. Остальные
   действия — `secondary` или `ghost`. Экран без `primary` имеет `btn-lg` в
   конце ленты.
3. **Короткий глагол.** Кнопка — действие, а не описание. «Купить», «Подать»,
   «Спать». Подпись > 24 символов — пересмотреть.
4. **44px тап-таргет, всегда.** Высота `--tap = 44px` минимум. Расстояние
   между таргетами ≥ 8px, чтобы не промахиваться.
5. **Движение = ответ.** Анимации короткие (120–220 мс), функциональные
   (вход, отклик, выплата). Никаких бесконечных переливов. Всё отключается
   при `prefers-reduced-motion`.

## 2. Кнопки

### 2.1. Типы

| Тип                | Класс                  | Когда                                       | Цвет      | Пример                       |
| ------------------ | ---------------------- | ------------------------------------------- | --------- | ---------------------------- |
| **Primary CTA**    | `.btn-primary`         | Главное действие экрана. **Одна на экран.** | gold      | «Завершить день», «Купить»   |
| **Secondary**      | `.btn-secondary`       | Следующее по важности, не главное           | ink/sky   | «Подробнее», «Примерить»     |
| **Ghost**          | `.btn-ghost`           | Тихие действия без побочных эффектов        | текст     | «Отмена», «Закрыть»          |
| **Success**        | `.btn-success`         | Подтверждение, бесплатный бонус             | moss      | «Забрать награду»            |
| **Danger**         | `.btn-danger`          | Удаление, необратимое, потеря               | clay      | «Удалить аккаунт»            |
| **Large CTA**      | `.btn-lg`              | Стартовый/финальный экран без альтернативы  | gold      | «Начать игру»                |
| **Tab bar item**   | `.tabbar-item`         | Нижняя навигация (см. §3)                   | tab-цвет  | «Главная», «Работа»          |
| **Action tile**    | `.tile-action`         | Действие дня: иконка + цена                 | tile-цвет | «Учиться (3 ⚡)»             |
| **Event choice**   | `.ev-choice`           | Выбор в случайном событии (см. §5)          | ev-цвет   | «Заплатить 500 ₽»            |
| **Icon only**      | `.btn` + `aria-label`  | Узкие действия, всегда с подписью для a11y   | как ghost | «🔙» BackButton (с label)    |

### 2.2. Размеры

| Размер        | Высота | Кегль | Радиус           | Когда                                |
| ------------- | ------ | ----- | ---------------- | ------------------------------------ |
| `.btn` (md)   | 44px   | 15px  | `--radius-control` (12px) | Большинство кнопок                   |
| `.btn-lg`     | 56px   | 17px  | 14px             | Стартовый экран, конец дня, покупки  |
| `.btn-sm`     | 32px   | 13px  | 10px             | Вторичные действия в карточке        |
| Tile          | 64–88px| 13–15 | `--radius-tile` (14px)   | Действия дня (большая иконка)        |
| Tab bar       | 54px   | 11px  | пилюля активного | Нижняя навигация                     |

### 2.3. Состояния

У каждой кнопки ровно пять визуальных состояний. В таблице ниже — что меняется
для `.btn-primary` (для других типов — те же оси, разные токены).

| Состояние       | Что меняется                                                                 | Токены                                    |
| --------------- | ---------------------------------------------------------------------------- | ----------------------------------------- |
| **Default**     | градиент, рамка, верхний блик                                                | `gold-300 → gold-500`, `--line-strong`    |
| **Hover**       | светлеет верхний блик, `transform: translateY(-1px)`                         | + `--glow-gold` (мягкое свечение)          |
| **Active/Press**| опускается на 1px, гаснет блик, появляется inset-тень                        | `brightness(0.97)`, `--shadow-pressed`    |
| **Disabled**    | `opacity 0.5`, `pointer-events: none`, `aria-disabled="true"`                | `gold-700` (тусклый), без градиента       |
| **Loading**     | спиннер 16px вместо подписи, `aria-busy="true"`, клики заблокированы         | сохраняет рамку primary, opacity 0.7      |

**Правила:**

- `disabled` ≠ `invisible`. Скрытая кнопка — антипаттерн (игрок не понимает,
  что действие появится позже). Лучше: показать disabled + tooltip-подсказку
  «Нужно 500 ₽» (chip под кнопкой).
- `loading` — только для сетевых действий (покупка, повышение, оффер). Для
  мгновенных действий (выбор события, выбор в меню) — оптимистичный апдейт
  без спиннера, откат + хаптика `error` при провале.
- `hover` работает **только** при наличии мыши; на тач-устройствах нажатие =
  `active` без предшествующего `hover`.

### 2.4. Иконки внутри кнопок

- Иконка слева от подписи, размер = высота текста (± 2px). Больше — кнопка
  визуально «ломается».
- Иконка `PixelIcon` (`currentColor`), не emoji. Эмодзи внутри кнопок — нет
  (разные рендеры на iOS/Android).
- Отступ иконка↔текст — 8px. Если только иконка — `aria-label` обязателен.

### 2.5. Содержимое кнопки (копирайт)

| Правило                                | Пример ✅              | Антипример ❌              |
| -------------------------------------- | --------------------- | ------------------------- |
| Глагол в инфинитиве, 1–3 слова         | «Купить», «Принять»   | «Подтвердить покупку»     |
| Без капслока                           | «Купить»              | «КУПИТЬ»                  |
| Без восклицательных знаков             | «Завершить день»      | «Завершить день!»         |
| Без «ОК», «Да», «Нет»                  | «Принять оффер»       | «ОК»                      |
| Числа — только цена/ресурс, форматом   | «Купить · 5 000 ₽»   | «Купить эту штуку»        |
| Склоняемые единицы (`+1`, `+2`, `+5`)  | «+3 XP», «−500 ₽»     | «+3 exp», «−500 рублей»   |

**Паттерны с ресурсами** (читаются как «купить за N»): «Купить · 5 000 ₽»,
«Спать (+8 ⚡)», «Учиться (3 ⚡)». Скобки — круглые, ресурс идёт первым.

## 3. Меню и навигация

### 3.1. Структура

**Нижние вкладки (5) — то, что игрок открывает каждый день:**

| Вкладка   | Экран         | Иконка        | Что внутри                                                                 |
| --------- | ------------- | ------------- | -------------------------------------------------------------------------- |
| Главная   | `DayView`     | `briefcase`   | Событие дня, действия, прогресс, кормление питомца, MainButton             |
| Работа    | `CareerView`  | `chart`       | Грейды, офферы, квиз, компании, `CareerPressureCard`                       |
| Обучение  | `SkillsView`  | `book`        | Дерево навыков (PoE-стиль), перки, английский                              |
| Магазин   | `ShopView`    | `bag`         | Товары, жильё, Stars-каталог                                               |
| Друзья    | `FriendsView` | `people`      | Социальные действия, контакты                                              |

**MORE-меню (9) — то, что открывается реже:**

| Раздел      | Экран              | Иконка       | Зачем                                              |
| ----------- | ------------------ | ------------ | -------------------------------------------------- |
| Профиль     | `ProfileView`      | `person`     | Статистика, бейджи, цели                           |
| Дом         | `RoomView`         | `house`      | Комната, гардероб, питомец, NFT, шар-карточка      |
| Цели        | `AchievementsView` | `trophy`     | 17 ачивок с прогрессом                             |
| Топ         | `LeaderboardView`  | `star`       | Живой рейтинг                                      |
| Офис        | `OfficeView`       | `screen`     | 5 NPC-портретов, задачи, настроение                |
| Майнинг     | `MiningView`       | `chip`       | Ферма, оборудование, прогноз                       |
| Кошелёк     | `WalletView`       | `box`        | NFT-инвентарь, привязка Solana                     |
| Питомец     | `PetView`          | `heart`      | Еда, настроение, аксессуары                        |
| Финалы      | `EndingView`       | `trophy`     | 6 финалов, клейм через `claim_ending`              |

**Правило:** 5 вкладок — лимит внимания. 6+ → «Ещё» (хаб-список).

### 3.2. Tab bar (нижняя навигация)

```
┌─────────────────────────────────────────────┐
│  ⚡ bolt    💼 chart    📚 book    🛍 bag  👥 people  │
│  День     Работа     Обучение  Магазин   Друзья  │
└─────────────────────────────────────────────┘
```

- Высота 54px + safe-area inset.
- Активная вкладка — золотая капсула (`--gold-300/15`) с золотой иконкой и
  золотой подписью. Неактивные — `--text-mute` (читаемо, не кричит).
- Точка-индикатор справа сверху у иконки — только когда **ждёт** (непрочитанный
  оффер, новая ачивка). Не для «уведомлений» ради уведомлений.
- `haptic: selection` при переключении.
- На десктопе (> 768px) tab bar прибит к низу 480px-контейнера, не к окну.

### 3.3. MORE-меню (хаб)

- **Список строк**, не сетка плиток. Каждая строка:
  ```
  ┌──┬───────────────────────────────┐──┐
  │🟫│ Профиль              Здесь › │
  │  │ Статистика и бейджи             │
  └──┴───────────────────────────────┘──┘
  ```
- Иконка в плашке-«сокете» 40×40 слева, заголовок + подсказка, стрелка `›`.
- Текущий раздел — золотая планка 3px слева + слово «здесь» справа.
- Тап → `haptic: selection` + переход.

**Почему список, а не сетка:** список сканируется взглядом за 1 секунду; сетка
одинаковых плиток заставляет сравнивать «что важнее» — когнитивная нагрузка.

### 3.4. BackButton

Telegram BackButton показывается, когда есть «куда назад»:

| Текущий экран   | BackButton | Что делает                  |
| --------------- | ---------- | --------------------------- |
| Вкладка «День»  | скрыта     | —                           |
| Любая MORE-вкладка | → MORE   | возвращает в хаб            |
| Модалка/детальный экран | → назад | закрывает модалку           |
| Квиз собеседования | → отказ   | подтверждение «выйти из квиза?» |
| Главное меню    | скрыта     | —                           |

В браузере (без Telegram) BackButton заменяется на программную кнопку «‹ Назад»
в шапке; поведение — то же.

## 4. UX-флоу

### 4.1. Онбординг (дни 1–7)

```
Telegram WebApp открыт
  → initData → POST /api/auth/telegram → JWT
  → POST /api/game/state → новый игрок (10 300 ₽, unemployed, 10 ⚡)
  → Главная (DayView)
       └── tip-карточка «Совет дня 1/7» — «Сначала устройся на работу»
            └── тап «Принято» → chip-стрик в HUD
       └── категория «Работа» (actions)
            └── «Откликнуться» → список вакансий
                 └── выбор → состояние «ожидание» (1–3 дня)
  → День 2–3: оффер, квиз собеседования
  → День 5: первый оффер принят → junior
```

**Принципы:**

- Совет дня — **один** на день, не «карусель». Игрок учится одному действию.
- `EmptyState` для пустых списков (нет офферов) всегда **с подсказкой**:
  «Откликнись на вакансии в разделе Работа».
- Прогрессивное раскрытие: сложные экраны (Майнинг, Кошелёк, Финалы) скрыты
  в MORE до дня 7+ ★ (рекомендация, не сделано).

### 4.2. Цикл дня (основной loop)

```
Главная (DayView)
  │
  ├─ Событие дня [EventCard] ────── 1 выбор ──┐
  │                                              │
  ├─ Действия (категории: Учёба / Работа /      │
  │   Соц. / Отдых / Хобби) — каждое тратит     │
  │   ⚡, даёт эффекты (деньги / XP / ...)      │
  │                                              │
  ├─ Кормление питомца (если есть)               │
  │                                              │
  └─ «Завершить день» [MainButton / btn-lg] ─────┘
       │
       ▼
   POST /api/game/advance-day
       │
       ├─ Списание living costs + зарплата (если работает)
       ├─ Случайное событие на завтра
       ├─ Офферы (если пришли)
       ├─ Хаптика: medium
       │
       ▼
   Главная (день +1)
```

**Критичные правила:**

- `MainButton` (Telegram) показывает **прогресс дня**: «День 5 · ⚡ 3» →
  «День 5 · ⚡ 1» в реальном времени. Не «Завершить день 5 →», а **текущее
  состояние**.
- В браузере (нет MainButton) — `.sticky-cta` внизу, тот же текст.
- Повторный тап после завершения = `error`-хаптика, ничего не происходит.

### 4.3. Покупка (ShopView)

```
Карточка товара [ShopItem]
  │
  ├─ Спрайт + название + категория
  ├─ «Описание» (свёрнуто по умолчанию, тап раскрывает)
  ├─ Цена: «5 000 ₽ · есть 12 000 ₽» — moss если хватает, ochre если нет
  └─ [Купить] (btn-primary) или [Не хватает] (disabled + tooltip)
       │
       ▼
   POST /api/game/action {actionId: 'buy_item', params: {id}, idempotencyKey}
       │
       ├─ OK → haptic: success, +N ₽ визуально улетает в шапку
       │        карточка сворачивается → «Куплено ✓» (moss chip)
       │
       └─ 400/402 → haptic: error, toast «Не хватает 1 000 ₽»
                    счётчик денег «трясётся» (300 мс)
```

**Почему idempotencyKey:** повторный тап при лагах сети не списывает дважды.
Ключ живёт 6 ч в самом сейве (см. README «Auth»).

### 4.4. Повышение грейда (CareerView)

```
CareerPressureCard [появляется, когда открыт гейт]
  │
  ├─ Требования: ✓ выучены, ✗ не хватает
  ├─ «Стоимость дня» (chip: −N ₽, если без работы)
  ├─ Прогресс по требованиям
  └─ [Попробовать] (btn-primary)
       │
       ▼
   POST /api/game/action {actionId: 'work_task'} или /advance-day
       │
       ├─ Ревью открыто → ожидание слота (1–7 дней)
       │     └── UI: чип «Ревью идёт, шанс 62%»
       │
       └─ Слот выпал → повышение + эффекты
              └── UI: карточка «Поздравляем, Senior!»
                    + ачивка «Senior за 78 дней» (если быстро)
                    + haptic: success
```

### 4.5. Финалы (EndingView)

```
6 финалов в балансе, проверки в state.endingsCanClaim():
  - cto (выборы)
  - exit (стартап ≥ 100 млн)
  - free_artist (senior + rep ≥ 40)
  - teacher (rep ≥ 60, 50+ менти)
  - burnout (мотивация/здоровье = 0, 7 дней)
  - left_it (деньги < 0, 15 дней)

EndingView → карточка с условиями (✓/✗)
  │
  └─ [Забрать финал] (btn-primary, доступно если ✓)
       │
       ▼
   POST /api/game/action {actionId: 'claim_ending', params: {id}}
       │
       ├─ OK → «жизнь завершена», «Новая жизнь» [btn-lg]
       │        metaXpMult +15% навсегда (потолок +75% = 5 жизней)
       │
       └─ Не выполнено → haptic: error, toast «Условия не выполнены»
```

## 5. Карточки событий (EventCard)

Случайное событие — **главный контент-нарратив**. Анатомия:

```
┌────────────────────────────────────────────────┐
│ ◰  [Тон: clay/ochre/gold/sky/moss]            │ ← panel-note + tone
│                                                │
│  [44×44 медальон]  Категория · gold            │ ← emoji-токен + tag
│  Заголовок события                             │
│                                                │
│  История в 1–3 предложения. Кто, где, что.     │
│  Без воды. Без «давным-давно».                │
│                                                │
│  ┌──────────────────────────────────────────┐  │
│  │ Выбор 1                       [−500 ₽]  │  │ ← ev-choice (moss/clay chip)
│  │ Подпись выбора                            │  │
│  └──────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────┐  │
│  │ Выбор 2                       [+2 ⚡]    │  │
│  │ Подпись выбора                            │  │
│  └──────────────────────────────────────────┘  │
│  ┌──────────────────────────────────────────┐  │
│  │ Выбор 3                       [+3 XP]    │  │
│  └──────────────────────────────────────────┘  │
└────────────────────────────────────────────────┘
```

**Правила:**

- 2–4 выбора, не больше. Больше → когнитивная перегрузка.
- Эффекты (`−500 ₽`, `+2 ⚡`, `★+1`) — **только из `effects` контента**,
  не придуманы в коде. Игрок видит правду.
- Цвет чипа эффекта: `moss` для плюса, `clay` для минуса, `gold` для
  репутации, `sky` для навыков.
- Тон карточки по тегу события (`EVENT_TONES` в `DayView`):
  - crisis/toxic → `clay`
  - reward → `gold`
  - работа/tech → `gold`
  - учёба → `sky`
  - деньги/майнинг → `moss`
  - люди/семья/питомцы → `sky`
  - здоровье → `moss`
  - цепочка → `sky`
  - default → `ochre`

## 6. Пустые состояния и ошибки

### 6.1. EmptyState

Каждый экран **обязан** иметь `EmptyState` для пустого списка. Структура:

```tsx
<EmptyState
  icon="box"        // имя пиксельной иконки
  title="Нет офферов"
  hint="Откликнись на вакансии в разделе Работа"
  cta={{ label: 'К вакансиям', to: 'career' }}
/>
```

**Реестр пустых состояний:**

| Экран             | Icon     | Title             | Hint                                              |
| ----------------- | -------- | ----------------- | ------------------------------------------------- |
| Офферы            | `briefcase` | «Нет офферов»     | «Откликнись на вакансии в Работе»                |

### 6.2. Ошибки сети

- `haptic: error` + toast (`.gain-float` стилизованный под `clay`).
- Текст: «Сеть потеряна. Попробуй ещё раз» (без кода ошибки, без стектрейса).
- Действие: кнопка `Повторить` в toast (5 секунд, потом исчезает).
- При 401 (сессия истекла) — автоматический refresh JWT, при провале —
  переход на онбординг с сохранением прогресса.

### 6.3. Ошибки валидации

- Inline под полем ввода, `clay` цвет, иконка `warn`.
- Без модалок. Игрок в Telegram не ждёт модалок.

## 7. Микровзаимодействия

### 7.1. Хаптика (Telegram WebApp)

| Событие                  | Тип        |
| ------------------------ | ---------- |
| Переключение вкладки     | `selection`|
| Выбор в событии          | `selection`|
| Действие (тап на тайл)   | `tap`      |
| Открыть/закрыть MORE     | `tap`      |
| Покупка                  | `medium`   |
| Конец дня                | `medium`   |
| Оффер принят             | `success`  |
| Ачивка получена          | `success`  |
| Финал получен            | `success`  |
| Ошибка / сеть / отказ    | `error`    |

**Правила:**

- Не больше **одной** `success` за 30 секунд (иначе игрок привыкает и не
  замечает).
- `error` — **только** на действия игрока, не на фоновые сетевые сбои.

### 7.2. Визуальная обратная связь

| Действие              | Анимация                                              | Файл                |
| --------------------- | ----------------------------------------------------- | ------------------- |
| Тап на кнопку         | Опускание 1px, гаснет блик, inset-тень (140 мс)       | `.btn:active`       |
| Число изменилось      | Счётчик подпрыгивает до 1.22×, 180 мс                | `usePop` (ResourceBar) |
| Выплата (+N ₽)        | Капсула улетает вверх 32px и тает, 600 мс             | `.gain-float`       |
| Появление карточки    | Slide-up 12px + fade, 220 мс                          | `.animate-slide-up` |
| Событие дня           | Карточка раскрывается из `ochre` тона                 | `EventCard`         |
| Переход экран→экран   | Cross-fade 120 мс, не slide (не работает в TMA)        | `GameScreen`        |
| Карта навыков, выучено| Пунктир «бежит» по ребру, бесконечно (gold→moss)     | `map-learned-flow`  |

**Отключение:** всё через `@media (prefers-reduced-motion: reduce)`. Никакая
анимация не должна нести **единственный** смысл — всегда есть статичное
состояние.

### 7.3. Звук

Сейчас нет (не входит в ближний план). Если добавлять — короткие, не
мелодичные, отключаемые в настройках, **не** срабатывающие без явного
действия игрока.

## 8. Адаптивность и safe-area

| Брейкпоинт | Ширина    | Поведение                                               |
| ---------- | --------- | ------------------------------------------------------- |
| XS         | ≤ 360px   | Одностолбцовый список, шрифт базовый, иконки 12px        |
| SM         | 361–480px | Планшет-режим не поддерживается, **mobile-first**        |
| MD         | 481–768px | Центрирование в 480px-контейнере, фон за ним — чернила  |
| LG         | > 768px   | 480px-рамка с тонкими боковыми линиями (стеклянный эффект) |

**Safe-area** (iOS, Telegram-обёртка):

- `.app-container` использует `env(safe-area-inset-*)` для верхнего/нижнего
  отступов.
- Tab bar приподнят на `env(safe-area-inset-bottom)`.
- Шапка — на `env(safe-area-inset-top)`.
- BackButton отступает от левого края на 8px + safe-area.

**Ландшафтный режим:** не оптимизирован (Telegram Mobile почти всегда
портретный); в ландшафте клиент работает, но может потребовать скролла.

## 9. Доступность (a11y)

Минимальный, но честный чек-лист. Каждый новый экран проходит по нему.

- [ ] **Контраст текста к фону ≥ 4.5:1** (WCAG AA). Использовать токены, не
      ручные цвета. `--text` на `--bg` = 13.4:1 ✅
- [ ] **Фокус видим** на всех интерактивах. `:focus-visible { outline: 2px
      solid var(--gold-300); outline-offset: 2px }`.
- [ ] **Тап-таргет ≥ 44×44px** для всех кнопок. Тайлы действий — больше.
- [ ] **Иконки без подписи** имеют `aria-label` (`<PixelIcon aria-label="Назад" />`).
- [ ] **Состояния `disabled`/`loading`** — `aria-disabled` / `aria-busy`.
- [ ] **Семантические роли**: `<button>` для действий, `<a>` для переходов,
      `<nav>` для tab bar, `<main>` для контента экрана.
- [ ] **Заголовки**: один `<h1>` на экран (через `ScreenTitle`), иерархия
      `<h2>`/`<h3>` внутри.
- [ ] **Анимации не обязательны**: `prefers-reduced-motion` отключает
      `gain-float`, `num-pop`, `map-learned-flow`, slide-up.
- [ ] **Числа читаемы**: `tabular-nums` (`.num`), не «дёргают» строку.
- [ ] **Ошибки — не цветом одним**: `aria-invalid="true"` + иконка + текст.

## 11. Что не входит в систему

Явные «нет», чтобы дизайнер не тратил время на правки.

- **Кастомные шрифты.** Используется системный стек. Шрифты в проде Telegram
  грузятся с задержкой и часто блокируются; системный шрифт — мгновенный и
  честный.
- **Эмодзи в хроме.** Только в контенте (навык, товар, ачивка) и только в
  рамке `EmojiToken`. В кнопках, вкладках, чипах — никогда.
- **Тени агрессивнее `--shadow-card`.** Тяжёлые тени в темной теме =
  «грязный» пиксельный мир. Тени слоистые, мягкие, на 1–2 уровня.
- **Скругления > 20px.** Карточка 18px, контрол 12px, таб-капсула пилюля.
  Больше — выглядит как Material, теряется пиксельный мир.
- **Анимации длиннее 300 мс.** Ощущение «лагает», особенно на старых Android.
- **Модалки подтверждения** (кроме необратимых действий). Игрок в Telegram не
  ждёт модалок — подтверждение через «двухшаговую кнопку» (5 с отмена).
- **Параллельные списки на одном экране** без явной иерархии. Один столбец
  с чёткой вертикальной структурой.

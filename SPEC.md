# ТЗ «IT Life Simulator» v2.0 — Telegram Mini App

Переработанное техническое задание на разработку.

## О проекте
Юмористический симулятор жизни IT-специалиста в формате Telegram Mini App.
Игрок начинает после института и строит карьеру, управляя ресурсами, расписанием и решениями.

## Стек технологий
- **Frontend:** React 18 + TypeScript + Tailwind CSS + Zustand
- **Backend:** Node.js + Fastify + TypeScript
- **База данных:** PostgreSQL + Prisma (JSONB для игрового состояния)
- **Telegram:** Mini App SDK, initData HMAC-валидация
- **Контент:** JSON-конфиги с Zod-схемами
- **Монорепозиторий:** npm workspaces

## Ключевые архитектурные решения

### 1. Сервер-авторитетная модель
Вся игровая логика — на сервере. Клиент отправляет намерение (intent),
сервер вычисляет эффекты. Клиент использует те же функции для оптимистичного
предпросмотра, но источник правды — сервер.

### 2. Offline-начисление энергии
1 игровой день = 3.5 реальных часа. Максимум 7 дней в банке.
Расчёт только по серверному времени.

### 3. Контент как данные
Весь гейм-контент в JSON. Правка баланса = правка JSON, без релиза клиента.
Валидация через Zod при старте сервера. Cross-reference проверка в CI.

### 4. Симулятор баланса
40 прогонов × 365 игровых дней. `npm test` гоняет его в режиме `--check`
(в CI при изменении конфигов — см. примечание ниже). Проверяет, что все карьерные
вехи в целевых коридорах, плюс комплаенс поздней игры:
`architect до 250-го дня ≤ 25%`, `доля архитекторов ≥ 50%`, `CTO за год ≤ 35%`
(эндгейм обязан оставаться трудным), `выгорания ≤ 20%`, `тупиков 0`.

### 5. Карьерные гейты и стоимость жизни (v2.1)
- Гейты грейдов — данные (`balance.careerGates`), а не константа в коде: глубина
  основного навыка, сумма по ветке, общая ширина, коммуникация/английский/лидерство,
  репутация, период ревью и конкуренция на место.
- Повышение открывается требованиями, но реализуют его слоты компании (вероятность
  зависит от перебора требований) — «впритык» тоже работает, просто медленно.
- Бытовые расходы (`livingCosts`) списываются каждый день, налог на капитал раз в месяц,
  переезд требует подушки `saveMult ×` платежа, удержанной `saveStreakDays` подряд.
- Мягкие навыки Saturate: нетворкинг ограничен (`networking.dailyCap`), выше порога
  насыщения XP идёт с демпфером — «митапы» нельзя фармить до бесконечности.
- Финалы ТЗ стали кодом: CTO — выборы борта (`cto_elect`, special-gate),
  `burnout` и «ушёл из IT» — терминальные состояния из `balance.endings`.

> ⚠ CI (.github/workflows) в репозитории до сих пор нет — проверка баланса выполняется
> локально через `npm test`. Добавление workflow — отдельная задача.

### 6. Процедурная генерация пиксельных персонажей (v2.2)
- Отдельный пайплайн вместо рукотворных спрайтов: AI отдаёт **пиксельную сетку в JSON**,
  валидатор её принимает/отвергает, генератор собирает комбинации, рендерер рисует PNG.
  Правки и дополнения к ТЗ — [docs/pixel-art.md](docs/pixel-art.md).
- Канвас фиксированный 32×32, анфас; слои `face → eyes → mouth → clothing → hair → hat → accessory`,
  каждый следующий полностью перекрывает предыдущий; прозрачность = отсутствие пикселя.
- Цвет только через палитру (`palette#индекс` или `palette#hlt|base|shd|outline`); литеральный hex
  разрешён в `hat`/`accessory` (металлопластика/стекло). Браузерная перекраска — замена массива палитры.
- Единственный механизм совместимости — `excludes`, и только на категории с `*_none`/`*_bald`.
- Воспроизводимость = `seed` + `sha256(components.json)` + `sha256(generator_config.json)`;
  `pixelgen repro` пересобирает партию и сверяет пиксели, а не имена файлов.
- Апскейл — nearest neighbour; в браузере тот же движок, что и в CLI
  (`packages/shared/src/engine/pixelArt.ts`), контент отдаёт `GET /api/content/pixel`.
- MVP-набор: 30 компонентов (3/5/4/6/5/4/3), 4 цветовые схемы, пространство комбинаций 86 400.

## Ресурсы игрока
- 💰 Деньги — early game ограничитель
- ❤️ Здоровье (0-100) — долгосрочный ресурс
- 🔥 Мотивация (0-100) — краткосрочный ограничитель
- ⚡ Энергия (3-16) — ресурс хода
- ⭐ Репутация (0-100) — гейт карьеры

## Этапы игры
- **Early Game (1-30):** «Выживание» — первый оффер
- **Mid Game (30-150):** «Рост» — мидл, сеньор
- **Late Game (150+):** «Влияние» — тимлид, архитектор

## 1. Что это за проект

Юмористический симулятор жизни IT-специалиста в формате **Telegram Mini App**. Игрок стартует после института
(10 000 ₽, без работы) и строит карьеру: учит навыки, работает, ходит на собеседования, получает повышения,
обрастает вещами, питомцами и подработками, следит за деньгами/здоровьем/мотивацией/энергией/репутацией.

npm-workspaces монорепо, 6 пакетов:

| Пакет | Роль | Объём |
|---|---|---|
| `packages/shared` | игровой движок (чистые функции) + Zod-схемы + типы | ~1.4k строк, 66 юнит-тестов |
| `packages/content` | весь контент в JSON (без кода) | 32 файла, ~350 KB |
| `packages/server` | Fastify 4, сервер-авторитет | ~2.6k строк, `routes/game.ts` — 1502 строк |
| `packages/client` | React 18 + Vite 5 + Tailwind + Zustand 4 | ~2.3k строк, 9 экранов |
| `packages/bot` | Telegram-бот | 1 файл, мок-заглушка |
| `packages/sim` | симулятор баланса + тулстатистика событий | 2 скрипта |

Всего на самой полной ветке: **192 файла, ~22 440 строк** кода/контента + 84 SVG-слоя.

## 4. Архитектура и ключевые решения (факт в коде)

**Сервер-авторитет.** 10 эндпоинтов в `game.ts`: `/state`, `/action`, `/advance-day`, `/event-choice`,
`/unlock-perk`, `/main-skill`, `/interview/start|answer|finish`, `/reset`. Клиент шлёт намерение,
эффекты считает сервер; `@itsim/shared` — чистые функции, одни и те же для сервера, клиента (оптимистичный
предпросмотр) и симулятора.

**Энергия = игровые дни.** 1 день = 3.5 реальных часа, банк до 7 дней, `bankedDays`, `lastTickAt`, оффлайн-начисление
только по серверному времени (в `/state` отдаётся `offlineDaysEarned`). Плюс текущий «ресурс хода» `energy/maxEnergy`.

**Хранилище.** `packages/server/data/<telegramId>.json`, атомарная запись (tmp + rename) + in-memory `Map`-кэш,
интерфейс узкий (load/save/delete) под замену на PostgreSQL/Prisma. NFT-реестр рядом: `data/nft_registry.json`.

**Генеративный визуал (DESIGN.md).** Детерминированный генотип: `sha256(wallet|telegramId)` → xmur3+mulberry32 →
weighted pick по слотам (HashLips-паттерн);grayscale SVG-слои красятся CSS-фильтрами (1 ассет × 12 цветов);
манифесты `content/layers/avatar_manifest.json` / `room_manifest.json` (zOrder, веса, редкость, исключения).
`MockNftProvider` по интерфейсу `NftProvider` → замена на Helius RPC не трогает роуты.
Кросс-коллекционные синергии (`cross_collections.json`): SMB Gen2 → +5% фриланс, Mad Lads → постер, DeGods → пёс.

**Контент как данные.** `contentService.loadContent()` на старте валидирует 14 групп файлов через Zod
и делает cross-reference проверки: `skill.X` / `relation.X` ключи эффектов (исторически молча вырезались схемой —
эффекты терялись), id веток навыков, id слоёв против `genetics.json`, id навыков в вопросах собеседований.

**Обучающие собеседования.** 56 вопросов, тир по грейду, topic-first раздача (сначала основной навык), ответы
с сервера не утекают, `interviewAnswerScore` 0.4–1.0 подмешивается в реальную `interviewChance`, за верный ответ +3 XP,
за неверный +2 XP (ошибка тоже приносит прогресс), объяснение после ответа.

## 7. Найденные баги и риски (конкретно, с местом)

1. **Identity split в dev-режиме — `isYou` врёт.** При пустом `BOT_TOKEN` `telegramAuthHook` подменяет любого
   пользователя с невалидным/битым токеном на `{id: 1, 'Dev'}` (`packages/server/src/middleware/telegramAuth.ts:96,105,112`).
   Проверено: состояние писалось в `data/4242.json` (initData парсился), а `/api/leaderboard/friends` с тем же заголовком
   показал `{"name":"Tester","isYou":false}` — потому что ранжирование шло по id=1. В проде (BOT_TOKEN задан) не сработает,
   но в превью/локально ломает лидерборд, «сессионность» и любые проверки на себя.
2. **`JWT_SECRET` дефолтится в `'dev-secret'`** (`routes/auth.ts:8`) — при забыленной переменной окружения токены подписываются
   известным ключом.
3. **Идемпотентность живёт в памяти процесса** (`completedActions` Map, `game.ts:77`) — после рестарта кэш пуст, повтор действия
   с тем же `idempotencyKey` пройдёт заново.
4. **Отсутствие пагинации/лимита в `gameStore.loadState`-обходе** — лидерборд читает все `data/*.json` синхронно на каждый запрос;
   на 10k игроков это блокирует event loop.
5. **Поздняя игра не сбалансирована** (см. §3: 100% architect) + медианные деньги ~99k при целях «корпоративный бог / экзит» —
   финалы (CTO, экзит за 100 млн, «ушёл из IT», «выгорание») в коде достижимы лишь формально, «выгорания»-концовка как таковой нет.
6. **Нет `PATCH`-уровня версионирования состояния:** `state.version = 1` присутствует, но миграций между версиями нет —
   правка JSON-контента не меняет уже сохранённые состояния, а изменение схемы сломает старые файлы без явной ошибки.
7. **`packages/content` — workspace без `package.json`** (в `npm workspaces` он перечислен, но пакета нет): `npm run build -w packages/content`
   и любая попытка «собрать контент» падает; проверка кросс-ссылок существует только внутри `contentService` при старте сервера.

### Что осталось сознательно

- **PostgreSQL/Prisma** — интерфейс хранилища узкий, миграции сейвов есть; переезд стоит делать
  вместе с решением про хостинг.
- **Prettier по всей базе** — в CI `continue-on-error`, чтобы переформатирование не смешивалось
  с содержательными диффами.
- **Поздняя игра** — по-прежнему главный геймплейный долг: финалы `exit`, `free_artist`, `teacher`
  описаны в `balance.endings`, но в цикле не реализованы; симулятор всё так же показывает
  100% архитекторов к 365-му дню.
